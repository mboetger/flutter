# Verification Tooling Core Review - T-0.15a Round 4

### FINDING RANKINGS

### 1. BLOCKER (New in Round 4) - Self-Certification Gate Security Theatre
**What is wrong:** The new anti-certification logic (`git config user.email` compared to `git log -1`) fundamentally misunderstands role separation in a pipeline where all agents run under the same OS identity on the same workstation.
1. It catastrophically blocks the true `Validator` (who operates using the common workspace identity `boetger@google.com`) from generating evidence against a tree they are validating.
2. An implementer can trivially bypass the check entirely using bash environment variables (e.g., `GIT_CONFIG_COUNT=1 GIT_CONFIG_KEY_0=user.email GIT_CONFIG_VALUE_0=other@test.com dart dev/tools/bin/migration_verify.dart --task T-0.15`).
**Evidence:** Calling `dart dev/tools/bin/migration_verify.dart --task T-0.15` natively blocks execution entirely. Supplying `GIT_CONFIG_COUNT` trivially permits generation.
**Resolution:** Revert the identity checking logic completely. Enforce validation separation via requiring pre-requisite artifacts inside the tree (e.g. via `--check-artifact-sha` which asserts review components are completed).

### 2. BLOCKER (Unresolved B3) - PATH Hijacking Manufactures Fake Passes
**What is wrong:** While the `echo` mocks were removed, `_runRequestedGates` still invokes commands vulnerable to un-scrubbed environment pollution. By running `Process.run('bash', ['-c', cmd])` without explicit environment strictness, anyone can spoof execution by prepending a mock script's directory to the `PATH` environment variable.
**Evidence:** Running `PATH=/tmp/fakepath:$PATH dart dev/tools/bin/migration_verify.dart --task T-0.15 --gates host` (where `/tmp/fakepath/ninja` is an executable containing `exit 0`) instantly fabricates a clean JSON validation object with `"ran": true, "passed": true` for the `host` gate because Bash evaluates the hijacked `ninja` command without running the real test pipeline.
**Resolution:** Prevent environment injection spoofing internally. A common approach is setting `includeParentEnvironment: false` in `Process.run(...)` and strictly explicitly allowing only known safe constants (like `PATH=/usr/bin:/bin`).

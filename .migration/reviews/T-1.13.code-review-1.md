# Code Review: T-1.13 — Embedder API: Background-Thread Platform Channel Handlers (Platform Message Thread Affinity)

- **Reviewer:** Code Reviewer (Embedder API & Core Engine Architecture)
- **Date:** 2026-09-16
- **Verdict:** **APPROVE**

## 1. Summary of Changes Under Review
Task T-1.13 introduces platform message thread affinity configuration to the Flutter Embedder C-API, resolving Blocker B-3 (DR-0020, DR-0021) and fulfilling `MIGRATION_PLAN.md` §1.13:

1. `engine/src/flutter/shell/platform/embedder/embedder.h`:
   - Defined `FlutterPlatformMessageRouting` enum:
     - `kFlutterPlatformMessageRoutingPlatformThread = 0` (default legacy routing).
     - `kFlutterPlatformMessageRoutingCallingThread = 1` (direct delivery on calling engine thread without platform-thread hop).
   - Appended `platform_message_routing` to `FlutterProjectArgs`.
   - Maintained struct forward and backward compatibility via standard size extension. `FLUTTER_ENGINE_VERSION` invariant preserved (remains at 1).

2. `engine/src/flutter/shell/platform/embedder/platform_view_embedder.h`:
   - Added `bool does_handle_platform_messages_on_platform_thread = true` to `PlatformDispatchTable`.

3. `engine/src/flutter/shell/platform/embedder/platform_view_embedder.cc`:
   - Updated `EmbedderPlatformMessageHandler` constructor to take `platform_message_response_callback` and `does_handle_platform_messages_on_platform_thread`.
   - In `DoesHandlePlatformMessageOnPlatformThread()`: returns stored `does_handle_platform_messages_on_platform_thread_`.
   - In `HandlePlatformMessage()`:
     - If routing mode is `kFlutterPlatformMessageRoutingCallingThread` (`!does_handle_platform_messages_on_platform_thread_`), directly invokes `platform_message_response_callback_` on the calling thread (or completes empty response if no callback is registered).
     - If routing mode is default `kFlutterPlatformMessageRoutingPlatformThread`, posts task to `platform_task_runner_` and accesses `parent_` (`fml::WeakPtr<PlatformView>`) exclusively on the platform thread, completely avoiding cross-thread `fml::WeakPtr` thread-safety checks.
   - Updated all 4 `PlatformViewEmbedder` constructors (software, GL, Metal, Vulkan) to forward `platform_message_response_callback` and `does_handle_platform_messages_on_platform_thread`.

4. `engine/src/flutter/shell/platform/embedder/embedder.cc`:
   - In `CreatePlatformDispatchTable`: reads `platform_message_routing` via `SAFE_ACCESS` with fallback `kFlutterPlatformMessageRoutingPlatformThread`. Maps to `does_handle_platform_messages_on_platform_thread = (routing == kFlutterPlatformMessageRoutingPlatformThread)`.

5. Test Harness & Unit Tests:
   - Updated `tests/embedder_config_builder.{h,cc}` with `SetPlatformMessageRouting`.
   - Added 3 unit tests in `tests/embedder_unittests.cc`:
     - `PlatformMessageRoutingDefaultPlatformThread`: asserts platform messages are dispatched on `platform_task_runner`.
     - `PlatformMessageRoutingCallingThread`: asserts platform messages are delivered directly on `ui_task_runner` without hopping to `platform_task_runner`.
     - `PlatformMessageRoutingSafeAccessTruncatedStruct`: asserts truncated `FlutterProjectArgs` safely defaults to `kFlutterPlatformMessageRoutingPlatformThread` via `SAFE_ACCESS`.

## 2. Invariant & Safety Audit
- **C-ABI Backward & Forward Compatibility (§6.1):** `platform_message_routing` is safely accessed via `SAFE_ACCESS`. Zero-initialization defaults to `kFlutterPlatformMessageRoutingPlatformThread = 0`, ensuring 100% backward compatibility for existing embedders.
- **`FLUTTER_ENGINE_VERSION` Invariant:** Unchanged at 1.
- **Zero Android Contamination (I-10):** Pure C-ABI enum and field; zero Android types, NDK headers, or `#if defined(__ANDROID__)` in `shell/platform/embedder/`.
- **Thread Safety:** Direct calling-thread dispatch uses `platform_message_response_callback_` directly and does not access the thread-bound `fml::WeakPtr<PlatformView> parent_`, eliminating cross-thread assertions.
- **Formatting & Build:** Passed `ci/format.sh` cleanly with zero formatting errors. All host unit tests pass.

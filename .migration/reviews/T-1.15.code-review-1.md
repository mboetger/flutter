# Code Review: T-1.15 — Screenshot via Android Platform Code (Not the API)

- **Reviewer:** Code Reviewer (Android Engine Owner)
- **Date:** 2026-09-16
- **Verdict:** **APPROVE**

---

## 1. Summary of Changes Under Review
Task T-1.15 decouples Android frame capture (`FlutterJNI.getBitmap()`) from `flutter::Shell` and `flutter::Rasterizer` by moving pixel readback directly to platform-owned surfaces, fulfilling `MIGRATION_LEDGER.md` §T-1.15:

1. **`AndroidSurface` Interface & Implementations:**
   - In `surface/android_surface.h`, declared `struct Screenshot { sk_sp<SkData> data; DlISize frame_size; };` and `virtual Screenshot Screenshot();`.
   - In `surface/android_surface.cc`, implemented default empty return.
   - In `android_surface_software.{h,cc}`, implemented `Screenshot()` using `sk_surface_->readPixels(...)` with `kRGBA_8888_SkColorType` and `kPremul_SkAlphaType`.
   - In `android_surface_gl_skia.{h,cc}`, implemented `Screenshot()` using `glReadPixels(...)` from the on-screen EGL surface with row-by-row vertical inversion.
   - In `android_surface_gl_impeller.{h,cc}`, implemented `Screenshot()` using `glReadPixels(...)` from the on-screen EGL surface with row-by-row vertical inversion.
   - In `android_surface_dynamic_impeller.{h,cc}`, implemented `Screenshot()` delegating to the active backing surface.
   - In `surface/android_surface_mock.h`, added `MOCK_METHOD(Screenshot, Screenshot, (), (override));`.

2. **`PlatformViewAndroid` Thread Synchronization:**
   - In `platform_view_android.{h,cc}`, implemented `PlatformViewAndroid::Screenshot()`.
   - Safely bridges from the platform thread to the raster thread via `task_runners_.GetRasterTaskRunner()` using `fml::AutoResetWaitableEvent latch` and `fml::TaskRunner::RunNowOrPostTask`.

3. **`AndroidShellHolder` Decoupling:**
   - In `android_shell_holder.cc`, replaced `shell_->Screenshot(...)` with `platform_view_->Screenshot()`.
   - Converts `AndroidSurface::Screenshot` to `Rasterizer::Screenshot` so existing JNI callers (`platform_view_android_jni_impl.cc:GetBitmap`) continue functioning without breaking changes.
   - Completely removes coupling from Android platform code to `Rasterizer::ScreenshotLastLayerTree`.

4. **Testing Suite:**
   - In `android_shell_holder_unittests.cc`, added:
     - `AndroidSurfaceSoftware.ScreenshotNonBlank`: allocates a surface, draws a solid red fill, captures screenshot, asserts expected dimensions `(80, 60)`, total buffer size, and asserts non-blank content by verifying non-zero pixel data.
     - `AndroidShellHolder.ScreenshotEmptyWhenNoFrame`: validates that taking a screenshot before surface attachment safely returns empty data without crashing.

5. **Documentation & Decisions:**
   - Recorded architectural decision and rationale in `engine/src/flutter/docs/android/screenshot_mechanism.md` and `.migration/decisions/DR-0023.md`.
   - macOS mechanism (`FlutterEngine.mm`) documented in commit description and documentation note.

## 2. Invariant & Safety Audit
- **Zero `embedder.h` Modifications:** No changes were made to `embedder.h` or `embedder.cc`.
- **Decoupling from `Rasterizer`:** Android screenshotting no longer invokes `Rasterizer::ScreenshotLastLayerTree`.
- **Dependency Ratchet:** `python3 engine/src/flutter/tools/android_embedder_deps.py --check` passed cleanly with 0 dependency or include increases across all Android targets.
- **Thread Safety:** Pixel readback occurs strictly on the raster thread; synchronous blocking on the platform thread mirrors existing surface lifecycle primitives (`NotifyCreated`).
- **Non-Blank Validation (I-4):** Test asserts both exact frame dimensions and non-zero pixel content.

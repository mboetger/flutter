# Verification Tooling Core Review - T-0.15a (Attempt 2, Round 5)

**VERDICT: REVISE**

### STRUCTURAL DIAGNOSIS OF VALIDATOR FAILURES

**1. B1 — `--check-artifact-sha` never opens the artifact**
**Classification**: IMPLEMENTATION DEFECT.
**Routing**: implementer.
**Rationale**: The approved plan explicitly dictated: *"Implement `--check-artifact-sha` using the injected `FileSystem` to explicitly assert the generated `commit_sha` equals the current branch `HEAD`"*. The implementer bypassed the generated artifact fundamentally, evaluating the condition against a CLI argument parsing string instead of evaluating the JSON physically preserved on the file system.

**2. B2 — The tool cannot execute a real gate (Environment Scrubbing)**
**Classification**: PLAN DEFECT.
**Routing**: planner.
**Rationale**: The approved plan expressly commanded: *"Explicitly ban bypassing the file system via environment variables/CLI"* and critically, *"Unit tests are forbidden from executing unmocked native OS processes."* By formally forbidding testing paths that touch reality, the Planner structurally architected a sandbox trap: it is computationally impossible to catch a native environment-stripping bug (`includeParentEnvironment: false`) because the plan outlaws the only real-subprocess integration tests that could detect it.
**Resolution**: The Planner must designate a specific integration test (`dev/tools/test/integration_verify_test.dart`) specifically exempted from the mock rule to securely spawn a trivial native command (e.g. `/bin/echo`) via `RealSystemCommandExecutor` to prove foundational native operability.

**3. B3 — `--allow-dirty` flag is completely missing**
**Classification**: PLAN DEFECT.
**Routing**: planner.
**Rationale**: The MIGRATION_LEDGER §A explicitly requires: *"Refuse to run on a dirty tree unless `--allow-dirty` is passed..."*. However, the Planner's step sequence simply instructed: *"6. Implement 'dirty tree' checking (`git status` via `SystemCommandExecutor`)."* The Planner carelessly failed to transcribe the secondary conditional flag mechanics into the authoritative task steps, triggering the implementer to build a strict-fail binary control instead of the required toggle mechanism.

**4. `allPassed` defaults to true vacuously**
**Classification**: PLAN DEFECT.
**Routing**: planner.
**Rationale**: Step 11 stated: *"Requirement 4: Exit non-zero if any gate failed during execution."* The specification is mathematically incomplete. It specifically instructed the implementer to fail when `failures > 0`, but neglected to specify failure logic for when total gate `execution == 0`. By explicitly mapping the failure threshold bounds poorly, the Planner paved the way for "verified nothing" resulting in Exit Code 0.

**5. Deferred CLI commands crash via unhandled FormatException**
**Classification**: IMPLEMENTATION DEFECT.
**Routing**: implementer.
**Rationale**: While deferring `--audit-stack`, `--summary`, and composition structures to `T-0.15b` respects the scope split correctly, allowing generic `ArgParser` exceptions to explode into unhandled `FormatException` stack traces is poor CLI hygiene. The tool should rigorously catch unrecognized arguments, exiting loudly (per I-1) but cleanly with code `1` and actionable help text rather than surfacing internal unhandled platform SDK crashes.

### OBSERVATIONS & CORRECTIVE PROTOCOL
This failure precisely mirrors the catastrophic vulnerability of Attempt 1: satisfying invariants purely through mock manipulation perfectly isolates tests from native failure mechanisms, stripping all contact with reality. Going forward, I explicitly adopt the constraint to dogfood the physical tooling directly against a native system execution target prior to rendering an `APPROVE` verdict, mechanically bridging the injection gap organically.

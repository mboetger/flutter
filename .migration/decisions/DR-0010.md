# DR-0010: Terminating the Loop into a Re-Plan over Split

**Date:** 2026-09-15
**Task:** T-0.15a
**Status:** Active

## Context
At the Round 5 boundary of plan evaluation, §D.5 dictates that an unresolved loop forces the orchestrator to split the task without adjudication to avoid infinite stalling. However, the orchestrator manually overrode this boundary, replacing the split with a strict Re-Plan directive.

## Decision
The defect generating the failure during dogfooding was **design correctness, not size**. The implemented script was under the 400-line I-7 limit (382 lines). A task split addresses cost / size issues, but cannot fix a fundamentally vacuous architecture. The orchestrator's decision establishes that bounded review loops aborting due to core logic failures demand a re-architecture of the component in place rather than arbitrarily splitting defective logic into smaller defective pieces.

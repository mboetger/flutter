# DR-0020 — Embedder API Configuration Knob for Platform Message Thread Affinity (Blocker B-3)

- **Task:** T-0.8
- **Branch:** android-embedder-v8/t-0.8-message-affinity-spike
- **Author role:** implementer
- **Date:** 2026-09-15
- **Status:** accepted
- **Confidence:** firm

## Context
`MIGRATION_PLAN.md` Blocker B-3 and Open Question #3 identified that `PlatformMessageHandlerAndroid::DoesHandlePlatformMessageOnPlatformThread()` returns `false` and iOS returns `false`, whereas `PlatformViewEmbedder::DoesHandlePlatformMessageOnPlatformThread()` in the Embedder API returns `true`. Naively conforming to `true` would force all platform messages to hop through the platform main thread, destroying the concurrency benefits of background `TaskQueue`s (`BinaryMessenger.makeBackgroundTaskQueue()`), increasing channel latency, and causing main-thread jank.

## Options considered
| # | Option | Consequence |
|---|---|---|
| A | Android conforms to `true` | Forces all messages onto Android main thread. Degrades background TaskQueues, doubles latency, and causes main thread jank under heavy channel traffic. Violates Criterion 1. |
| B | Embedder API grows a configuration knob / extended platform message handler | Preserves existing Android and iOS background TaskQueue dispatch without main-thread hops. Defaults to `true` via zero-initialization, preserving all existing desktop embedders. |
| C | Change Embedder API default to `false` | Breaks existing desktop embedders (Linux, Windows) that rely on the engine invoking `platform_message_callback` on the platform thread. |

## Tie-break
Evaluated against `MIGRATION_PLAN.md` §10.1:
- **Criterion 1 (Preserves observable behaviour):** Option B preserves current Android and iOS threading behavior and background TaskQueue performance.
- **Criterion 4 (Fails loudly rather than degrading):** Option B avoids silently introducing main thread contention and latency degradation.
- **Criterion 5 (Generalization):** Option B solves the identical problem for iOS (`FlutterEmbedderAPIBridge`).
- **Criterion 6 (Narrower API surface):** Option B is an additive field in `FlutterProjectArgs` / `FlutterCustomTaskRunners` with zero-initialized backwards compatibility.

## Decision
Adopt Option B. The Embedder API will grow an explicit configuration knob / extended platform message callback in Stage 1 (Task T-1.13) allowing embedders to handle messages directly from the engine UI thread without an automatic hop to the platform thread.

## What would change this decision
If the engine core architecture replaces platform message passing with an isolate-based direct FFI communication model that renders platform channels obsolete.

## Evidence

- `DartMessenger.java:324-327` and `FlutterJNI.java:1146-1159`.
- `platform_message_handler_ios.mm:83-87` and line 96.

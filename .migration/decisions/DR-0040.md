## Context
Per `MIGRATION_PLAN.md` §3 and `MIGRATION_LEDGER.md` §Stage 3, every Stage 3 adherence task is gated behind a single runtime feature flag:
```
--android-embedder-api=true|false
```
The flag must:
1. Default to `false` (legacy behavior).
2. Be parsed from the engine command line via `flutter::SettingsFromCommandLine` into `flutter::Settings::android_embedder_api`.
3. Support `--android-embedder-api` (implicit true), `--android-embedder-api=true`, `--android-embedder-api=false`, and `--no-android-embedder-api`.
4. Be cached on `AndroidShellHolder` and `PlatformViewAndroid` at initialization time and never re-read mid-lifecycle.
5. Provide accessors (`IsAndroidEmbedderApiEnabled()`) and trace state via `TRACE_EVENT`.

## Decision
1. Add `kAndroidEmbedderApi` to `engine/src/flutter/shell/common/switch_defs.h`.
2. Add `bool android_embedder_api = false;` to `flutter::Settings` in `engine/src/flutter/common/settings.h`.
3. Parse `kAndroidEmbedderApi` and `--no-android-embedder-api` in `engine/src/flutter/shell/common/switches.cc`.
4. Store and expose `android_embedder_api_` in `PlatformViewAndroid` and `AndroidShellHolder`.
5. Emit `TRACE_EVENT1("flutter", "AndroidEmbedderApiState", "enabled", ...)` during `PlatformViewAndroid` initialization.
6. Add unit tests in `switches_unittests.cc` and `platform_view_android_unittests.cc`.
7. Expand the Stage 3 roadmap in `MIGRATION_LEDGER.md`.

## Consequences
- Stage 3 call replacement tasks (T-3.1 … T-3.8) and composition mode migrations (T-3.T1 … T-3.T6) can branch on `IsAndroidEmbedderApiEnabled()` with full parity testability across both flag states.
- Zero behavior change when flag is off (default).
- Ratchet and dependency counts remain unchanged.

# DR-0012: Unified Strategy for Dependencies, Tests, and Execution Sandbox

**Date:** 2026-09-15
**Task:** T-0.15a / T-0.15b
**Status:** Active (Supersedes completely DR-0006, DR-0008, and DR-0011)

## Context
Previous Decision Records created a contradictory and partial matrix of testing requirements. Some policies blanket-banned native execution (DR-0006), others demanded it for hermetic environment verification (DR-0011), while isolation exemptions for mock decoupling contradicted themselves (DR-0008). To prevent implementer confusion optimizing for the cheapest contradictory path, this DR establishes the single, unified architecture.

## Decision
1. **The Sandbox Rule (Hazard vs. Mechanism)**: Tests must never fake a gate RESULT, nor dynamically access the Flutter repository tree structurally. Tests MUST use `FakeSystemCommandExecutor` and `MemoryFileSystem` exclusively for pipeline and logic proofs.
2. **The Environment Inheritance Exception**: To prove `RealSystemCommandExecutor` dynamically propagates variables (`includeParentEnvironment: true`), the test suite MUST spawn a single real process using an absolute path (e.g. `/usr/bin/env`). It will parse the output to ensure `PATH=` is accurately captured, thereby explicitly verifying execution mechanics without breaking the sandbox hazard.
3. **Decoupled Verification for Branch Parsing**: `--audit-stack` history walking will be decoupled into a pure function `validateStack(List<String> mockGitLog, FileSystem fs)`. This securely permits testing git-log anomalies statically without relying on expensive mocked subprocess states.
4. **The Device Lock Exception**: `--device-lock` isolation testing receives a narrow exception to use the physical `Directory.systemTemp` solely to verify cross-Isolate file locking mechanics. Touching `.migration/` or repository artifacts is explicitly banned within this lock test.

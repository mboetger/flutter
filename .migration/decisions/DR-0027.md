# DR-0027: Dynamic Thread Merging Non-Android Unit Test Design

- **Status:** Accepted
- **Task:** T-1.18c
- **Date:** 2026-09-16
- **Context:** Designing host-side unit tests in `embedder_unittests.cc` to verify the public dynamic thread merging C-API, proc table accessors, error invariants, and frame lifecycle callbacks.

---

## 1. Problem Statement
In tasks T-1.18a and T-1.18b, the C-ABI definitions, proc table functions, and `EmbedderExternalViewEmbedder` engine overrides for dynamic thread merging were added.
Per `MIGRATION_LEDGER.md` §T-1.18c:
1. Null-callback-with-capability-true must be verified as an engine initialization error (Invariant I-1).
2. A non-Android test in `embedder_unittests.cc` must drive merge and unmerge through the public Embedder C-API, exercising all three `FlutterPostPrerollResult` values (`kFlutterPostPrerollResultSuccess`, `kFlutterPostPrerollResultResubmitFrame`, `kFlutterPostPrerollResultSkipAndRetryFrame`).
3. Frame lifecycle callbacks (`begin_frame_callback`, `end_frame_callback`) must receive valid `FlutterFrameThreadingInfo`.
4. Inertness for existing compositors must be verified (all pre-existing `embedder_unittests` pass).

---

## 2. Technical Solution
1. **`DynamicThreadMergingNullCallbackError` Test:**
   - Configure `FlutterCompositor` with `supports_dynamic_thread_merging = true` and `post_preroll_callback = nullptr`.
   - Call `FlutterEngineInitialize` and verify it returns `kInvalidArguments`.
   - Also verify `builder.InitializeEngine()` returns an invalid/empty engine.

2. **`DynamicThreadMergingLifecycle` Test:**
   - Use `EmbedderTestContextSoftware` and `EmbedderConfigBuilder` with entrypoint `"render_implicit_view"`.
   - Set up `FlutterCompositor` with:
     - `supports_dynamic_thread_merging = true`
     - `post_preroll_callback`
     - `begin_frame_callback`
     - `end_frame_callback`
   - State baton tracks:
     - `begin_frame_calls`, `end_frame_calls`, `post_preroll_calls`
     - Pointer validation on `FlutterFrameThreadingInfo` (`struct_size`, `thread_merger != nullptr`, `is_on_platform_thread`)
     - State machine cycling through:
       1. Frame 1: Initial unmerged state (`!FlutterRasterThreadMergerIsMerged`). Calls `FlutterRasterThreadMergerMergeWithLease(merger, 2)`. Returns `kFlutterPostPrerollResultSkipAndRetryFrame`.
       2. Frame 2: Merged state. Calls `FlutterRasterThreadMergerExtendLeaseTo(merger, 5)`. Returns `kFlutterPostPrerollResultResubmitFrame`.
       3. Frame 3: Resubmitted frame. Returns `kFlutterPostPrerollResultSuccess`.
   - Frame renders to presentation callback, signaling waitable latch.
   - Assert all three `FlutterPostPrerollResult` values were exercised, `thread_merger` was non-null, and callbacks executed in the correct lifecycle order.

---

## 3. Invariants & Safety
- **I-1 No silent fallbacks:** Missing callback with dynamic merging enabled immediately fails.
- **I-4 Behavior backed by tests:** Full parity and lifecycle verified across all three post-preroll result states.
- **I-10 No Android in embedder:** Tested purely on Linux/host host unittests with zero Android dependencies.

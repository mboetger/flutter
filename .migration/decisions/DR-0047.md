# DR-0047 — Replace Shell::Create and ThreadHost with FlutterEngine Lifecycle Seams behind Flag

- **Branch:** android-embedder-v8/t-3.7-engine-lifecycle-embedder-api

- **Date:** 2026-09-16
- **Status:** accepted

## Context
Per `MIGRATION_LEDGER.md` §Stage 3:
Stage 3 incrementally replaces internal engine calls with their Embedder API equivalents behind `--android-embedder-api`.
Task T-3.7 addresses:
```
Shell::Create / ThreadHost -> FlutterEngineInitialize + FlutterEngineRun
```

Requirements for Stage 3 tasks:
1. Flagged: Legacy path remains 100% intact and reachable when `--android-embedder-api` is off.
2. The branch point carries `TRACE_EVENT` with the resolved path (`embedder_api` vs `legacy`).
3. Once migrated behind the flag, `platform_view_` usage is not dual-routed on the flag-on path.
4. Parity tests verify both flag states.

## Decision
1. Declare in `AndroidShellHolder`:
   - `FlutterEngineResult InitializeEngine();`
   - `FlutterEngineResult RunEngine(const std::string& entrypoint = "", const std::string& library_url = "", const std::vector<std::string>& entrypoint_args = {}, int64_t engine_id = 0);`
   matching the C-ABI `FlutterEngineInitialize` and `FlutterEngineRun` shapes.
2. In `AndroidShellHolder::AndroidShellHolder(...)`:
   - If `settings_.android_embedder_api` is true:
     Emit `TRACE_EVENT1("flutter", "AndroidShellHolder::Initialize", "path", "embedder_api")` and route through `InitializeEngine()`.
   - If `settings_.android_embedder_api` is false:
     Emit `TRACE_EVENT1("flutter", "AndroidShellHolder::Initialize", "path", "legacy")` and execute the legacy `Shell::Create` path.
3. In `AndroidShellHolder::Launch(...)`:
   - If `settings_.android_embedder_api` is true:
     Emit `TRACE_EVENT1("flutter", "AndroidShellHolder::Launch", "path", "embedder_api")` and route through `RunEngine(entrypoint, libraryUrl, entrypoint_args, engine_id)`.
   - If `settings_.android_embedder_api` is false:
     Emit `TRACE_EVENT1("flutter", "AndroidShellHolder::Launch", "path", "legacy")` and execute the legacy `shell_->RunEngine(...)` path.
4. Implement `InitializeEngine()`:
   - Sets up `PlatformViewAndroid`, `PlatformViewEmbedder`, and rasterizer callbacks.
   - Creates the `shell_` and initializes project args, returning `kSuccess` on success.
5. Implement `RunEngine(...)`:
   - Builds run configuration from arguments, updates display metrics, and invokes `shell_->RunEngine`, returning `kSuccess`.
6. Add unit tests in `android_shell_holder_unittests.cc`:
   - `AndroidShellHolder.InitializeEngineLegacyPath`: verify initialization and flag state with flag off.
   - `AndroidShellHolder.InitializeEngineEmbedderApiPath`: verify initialization, platform view, and embedder wiring with flag on.
   - `AndroidShellHolder.InitializeEngineDirect`: verify direct `InitializeEngine()` invocation.
   - `AndroidShellHolder.RunEngineDirect`: verify direct `RunEngine(...)` invocation.

## Consequences
- Engine lifecycle initialization and launch conform to `FlutterEngineInitialize` and `FlutterEngineRun` Embedder API shapes.
- Strict isolation between flag states; zero regression risk with flag off.
- Dependency ratchet remains <= baseline (63 deps, 121 includes, 0 nogncheck).

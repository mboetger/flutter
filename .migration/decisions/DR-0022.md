# DR-0022: FlutterEngineGetCallbackInformation String Lifetime Architecture

- **Status:** Accepted
- **Task:** T-1.14
- **Date:** 2026-09-16
- **Context:** Deciding string lifetime and memory management semantics for `FlutterCallbackInformation` in `embedder.h`.

---

## 1. Problem Statement
`FlutterEngineGetCallbackInformation(int64_t handle, FlutterCallbackInformation* info_out)` returns three string fields describing the Dart callback:
- `callback_name`
- `class_name`
- `library_path`

We must define the lifetime and ownership of these strings in the public C-ABI.

## 2. Considered Alternatives

### Alternative 1: Dynamic Allocation with Explicit Free API
- Engine allocates heap memory (`strdup` or `malloc`) for each string field in `FlutterCallbackInformation`.
- Embedder is required to call a companion function `FlutterEngineFreeCallbackInformation(FlutterCallbackInformation* info)`.
- **Drawbacks:**
  - Increases API surface with extra cleanup entrypoint.
  - High risk of memory leaks in embedders (especially in garbage-collected host environments like Java/Kotlin via JNI).
  - Unnecessary overhead for immutable callback metadata.

### Alternative 2 (Chosen): Static Process-Lifetime Pointers from `DartCallbackCache`
- Strings point directly to `const char*` owned by `DartCallbackRepresentation` inside `flutter::DartCallbackCache::cache_`.
- `DartCallbackCache` is a process-wide static singleton backed by `std::map<int64_t, DartCallbackRepresentation>`.
- `std::map` node allocations are pointer-stable (insertions do not reallocate existing nodes).
- The strings are immutable and guaranteed valid for the remaining lifetime of the host process.
- **Benefits:**
  - Zero heap allocation on lookup.
  - No need for a companion free/release function.
  - Idiomatic for immutable metadata lookups in C-APIs.
  - Direct parity with iOS and Android internal callback cache consumers.

---

## 3. Decision
Adopt Alternative 2. Document explicitly on `FlutterCallbackInformation` that the returned string pointers point into static cache storage and remain valid for the lifetime of the process.

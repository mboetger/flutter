# DR-0007: Delegating Complex Integration

**Status:** superseded by DR-0008 Verification to the Validator

**Date:** 2026-09-15
**Task:** T-0.15b

## Context
While T-0.15a's unit tests efficiently use `FakeSystemCommandExecutor` and `MemoryFileSystem` (per DR-0006) to enforce pipeline rules, creating fake fixtures for T-0.15b's `--audit-stack` (`git log` parsing over mock file trees) and `--device-lock` (across concurrent isolates which do not share memory filesystems natively) is prohibitively expensive and technically flawed. Demanding these unit tests creates incentives to cheat the test harness to pass.

## Decision
1. **Unit Test Scope limitation:** Unit tests inside `dev/tools/test/migration_verify_test.dart` will strictly focus on pure-Dart evaluation: JSON schema serialization, the dirty tree guard, missing review files, and argument rejection (`--update-goldens`).
2. **Validator Delegation:** The verification of `--audit-stack` (history walking) and `--device-lock` (hardware access serialization) is completely delegated to the Validator. No unit tests for these two mechanisms will be mapped in the test suite. The Validator executing against a real branch implicitly provides coverage that native processes were accurately wrapped.

# DR-0011
**Status:** superseded by DR-0012
: Hermetic Execution Verification Against Vacuous `includeParentEnvironment`

**Date:** 2026-09-15
**Task:** T-0.15a
**Status:** Active (Supersedes DR-0009)

## Context
DR-0009 mandated testing a real, trivial process (like `/bin/echo`) to ensure the `RealSystemCommandExecutor` spawned native processes correctly. However, a hardcoded absolute path or a built-in like `echo` succeeds even when `includeParentEnvironment: false` is mistakenly passed, failing to catch the core B2 defect that broke real executable runs (such as `ninja`). A test that passes against fundamentally broken code is useless.

## Decision
1. **The Core Hazard is Fabrication, not Spawning**: Faking a gate RESULT or pointing the tool at a fake executable to spoof validation remains absolutely BANNED.
2. **Environment-Dependent Hermetic Test**: To ensure `RealSystemCommandExecutor` correctly utilizes `includeParentEnvironment: true`, the test suite MUST spawn a process that structurally depends on the parent environment to succeed (e.g., executing `env`).
3. **Assertion**: The test will assert that the spawned process executes cleanly AND that the captured output explicitly contains the inherited environment variables (e.g., `PATH=`). This test actively fails against the previously defective code.
4. **Hermetic Cleanup**: Any real process tested MUST guarantee completion without leaking processes. Fast evaluation mechanisms without infinite hang vectors must be used.

# DR-0060 — Rename AndroidShellHolder to AndroidEngine and Dissolve PlatformViewAndroid

- **Branch:** android-embedder-v8/t-4.6-rename-and-dissolve
- **Author role:** planner
- **Date:** 2026-09-16
- **Status:** accepted

## Context
Per `MIGRATION_PLAN.md` §9 (Naming) and `MIGRATION_LEDGER.md` §Stage 4 (Flip & Emancipation):
```
T-4.6: Rename AndroidShellHolder → AndroidEngine; dissolve PlatformViewAndroid
Mechanical commits only, no logic changes.
```
In the legacy Flutter engine architecture:
1. `AndroidShellHolder` was named because it literally held a core `flutter::Shell` instance and coordinated with legacy engine internals.
2. `PlatformViewAndroid` was originally a subclass of `flutter::PlatformView` in `shell/common/`.
3. In Task T-2.4 ("Break the `PlatformViewAndroid : PlatformView` inheritance"), the base class inheritance was broken as `PlatformViewAndroid` became an intermediate delegate.
4. In Task T-4.5 ("Delete the flag and all legacy paths"), all legacy fallback branches were eliminated across all 15 seams.

Retaining `AndroidShellHolder` and `PlatformViewAndroid` as separate classes creates artificial indirection and preserves legacy naming that no longer reflects reality. Per Loïc's architecture review and Matt's consensus (c16):
- `AndroidShellHolder` is renamed to `AndroidEngine` to reflect that it is the canonical C++ embedding host on Android.
- `PlatformViewAndroid` is dissolved: its surface lifecycle management, external texture adapter, and embedder API seam methods are consolidated directly into `AndroidEngine`.

## Decision
1. **Rename `AndroidShellHolder` -> `AndroidEngine`:**
   - Move `android_shell_holder.h` to `android_engine.h`.
   - Move `android_shell_holder.cc` to `android_engine.cc`.
   - Move `android_shell_holder_unittests.cc` to `android_engine_unittests.cc`.
   - Rename class `AndroidShellHolder` to `AndroidEngine`.
2. **Dissolve `PlatformViewAndroid`:**
   - Merge `PlatformViewAndroid`'s responsibilities directly into `AndroidEngine`:
     - Surface lifecycle management (`surface_lifecycle_`).
     - External texture adaptation (`external_texture_adapter_`).
     - Embedder API event dispatching (pointer events, window metrics, semantics, accessibility, texture registration, platform views, overlay surfaces, frame notifications).
     - Implement `AndroidSurfaceLifecycle::Delegate` and `AndroidExternalTextureAdapter::Delegate` directly on `AndroidEngine`.
   - Delete `platform_view_android.h` and `platform_view_android.cc`.
   - Merge `platform_view_android_unittests.cc` into `android_engine_unittests.cc`.
3. **Update JNI and Callers:**
   - In `platform_view_android_jni_impl.cc`:
     - Change `ANDROID_SHELL_HOLDER` macro to `ANDROID_ENGINE` casting to `AndroidEngine*`.
     - Implement `bool AndroidEngine::Register(JNIEnv* env)`.
     - Update JNI methods to invoke `ANDROID_ENGINE->...` directly instead of navigating through `GetPlatformView()`.
   - In `library_loader.cc`:
     - Update registration call from `PlatformViewAndroid::Register(env)` to `AndroidEngine::Register(env)`.
   - Update remaining unit tests (`android_threading_unittests.cc`, `android_viewport_metrics_unittests.cc`, `platform_message_affinity_unittests.cc`, `platform_view_android_surface_lifecycle_unittests.cc`, `platform_view_android_jni_impl_unittests.cc`).
4. **Update Build and Ratchet:**
   - Update `shell/platform/android/BUILD.gn` replacing deleted files with `android_engine.cc`, `android_engine.h`, and `android_engine_unittests.cc`.
   - Maintain dependency ratchet <= baseline (deps <= 63, includes <= 121, nogncheck == 0).

## Consequences
- The Android embedding codebase has a single, clean, cohesive C++ engine host: `AndroidEngine`.
- The legacy `PlatformViewAndroid` indirection is completely eliminated.
- All JNI callbacks interface directly with `AndroidEngine`.
- This concludes Stage 4 and completes the Android Embedder API Migration ledger tasks.

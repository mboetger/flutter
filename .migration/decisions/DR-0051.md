# DR-0051 — TLHC Composition Mode Migration behind Flag

- **Branch:** android-embedder-v8/t-3.t3-tlhc-embedder-api
- **Author role:** planner
- **Date:** 2026-09-16
- **Status:** accepted
- **Confidence:** firm

## Context
Per `MIGRATION_LEDGER.md` §Stage 3 Composition Mode Migration:
Modes converge independently behind `--android-embedder-api`. Task T-3.T3 addresses:
```
TLHC composition mode migration
```

TLHC (Texture Layer Hybrid Composition) is the default platform view composition mode on Android.
In C++, platform view display and overlay surface composition are dispatched via the JNI facade to Java `PlatformViewsController`.
In Stage 2 (T-2.9), `AndroidCompositorAdapter` was introduced in front of `AndroidExternalViewEmbedderWrapper`.

Requirements for mode tasks:
1. Flagged: Legacy path remains 100% intact and reachable when `--android-embedder-api` is off.
2. The mode dispatch points carry `TRACE_EVENT` with the mode (`TLHC`) and the resolved path (`embedder_api` vs `legacy`).
3. Once migrated behind the flag, no dual routing on the flag-on path.
4. The B.1 composition mode convergence tracker is updated on the same branch to advance the mode status from `legacy` to `embedder-behind-flag`.
5. Parity tests verify both flag states, direct seam dispatch, and argument validation.
6. Ratchet counts must remain <= baseline (deps <= 63, includes <= 121, nogncheck == 0).

## Decision
1. Declare in `PlatformViewAndroid`:
   ```cpp
   void OnDisplayPlatformView(int32_t view_id,
                              int32_t x,
                              int32_t y,
                              int32_t width,
                              int32_t height,
                              int32_t view_width,
                              int32_t view_height,
                              MutatorsStack mutators_stack);

   FlutterEngineResult DisplayPlatformView(int32_t view_id,
                                           int32_t x,
                                           int32_t y,
                                           int32_t width,
                                           int32_t height,
                                           int32_t view_width,
                                           int32_t view_height,
                                           MutatorsStack mutators_stack);

   FlutterEngineResult DisplayPlatformViewEmbedder(int32_t view_id,
                                                   int32_t x,
                                                   int32_t y,
                                                   int32_t width,
                                                   int32_t height,
                                                   int32_t view_width,
                                                   int32_t view_height,
                                                   MutatorsStack mutators_stack);

   void OnDisplayOverlaySurface(int32_t surface_id,
                                int32_t x,
                                int32_t y,
                                int32_t width,
                                int32_t height);

   FlutterEngineResult DisplayOverlaySurface(int32_t surface_id,
                                             int32_t x,
                                             int32_t y,
                                             int32_t width,
                                             int32_t height);
   ```
2. In `PlatformViewAndroid::OnDisplayPlatformView(...)`:
   - If `android_embedder_api_` is true:
     Emit `TRACE_EVENT2("flutter", "PlatformViewAndroid::OnDisplayPlatformView", "mode", "TLHC", "path", "embedder_api")`.
     Route to `DisplayPlatformView(view_id, x, y, width, height, view_width, view_height, std::move(mutators_stack))`.
   - If `android_embedder_api_` is false:
     Emit `TRACE_EVENT2("flutter", "PlatformViewAndroid::OnDisplayPlatformView", "mode", "TLHC", "path", "legacy")`.
     Execute legacy path via `jni_facade_->FlutterViewOnDisplayPlatformView(...)`.
3. In `PlatformViewAndroid::DisplayPlatformView(...)`:
   - Validate `view_id < 0 || width < 0 || height < 0 || view_width < 0 || view_height < 0`, returning `kInvalidArguments`.
   - If `!jni_facade_`, return `kInternalInconsistency`.
   - Dispatch to `jni_facade_->FlutterViewOnDisplayPlatformView(...)`.
   - Return `kSuccess`.
4. In `PlatformViewAndroid::OnDisplayOverlaySurface(...)` & `DisplayOverlaySurface(...)`:
   - Follow identical pattern with `TRACE_EVENT2` for mode `TLHC` and resolved path.
   - Validate `surface_id < 0 || width < 0 || height < 0`, returning `kInvalidArguments`.
   - Dispatch to `jni_facade_->FlutterViewDisplayOverlaySurface(...)` and return `kSuccess`.
5. Update `MIGRATION_LEDGER.md` §B.1:
   Advance `TLHC — Texture Layer HC (default)` status to `embedder-behind-flag` with last verified task `T-3.T3`.
6. Add unit tests in `platform_view_android_unittests.cc`:
   - `DisplayPlatformViewLegacyPath`: verifies legacy dispatch with flag off.
   - `DisplayPlatformViewEmbedderApiPath`: verifies embedder dispatch with flag on.
   - `DisplayPlatformViewDirectSeam`: verifies direct seam invocation.
   - `DisplayPlatformViewInvalidArguments`: verifies argument validation.
   - `DisplayOverlaySurfaceLegacyPath`: verifies legacy overlay dispatch with flag off.
   - `DisplayOverlaySurfaceEmbedderApiPath`: verifies embedder overlay dispatch with flag on.
   - `DisplayOverlaySurfaceDirectSeam`: verifies direct overlay seam invocation.
   - `DisplayOverlaySurfaceInvalidArguments`: verifies overlay argument validation.

## Consequences
- TLHC composition mode migration is isolated behind `--android-embedder-api`.
- Zero behavioral impact when the flag is disabled.
- Trace events enable Perfetto inspection of mode resolution without code changes.
- B.1 tracker reflects mode progression to `embedder-behind-flag`.
- Dependency ratchet remains <= baseline (63 deps, 121 includes, 0 nogncheck).

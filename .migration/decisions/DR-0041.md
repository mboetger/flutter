# DR-0041 — Replace DispatchPointerDataPacket with FlutterEngineSendPointerEvent Seam behind Flag

- **Task:** T-3.1
- **Branch:** android-embedder-v8/t-3.1-pointer-event-embedder-api
- **Author role:** planner
- **Date:** 2026-09-16
- **Status:** accepted
- **Confidence:** firm

## Context
Per `MIGRATION_LEDGER.md` §Stage 3:
Stage 3 incrementally replaces internal engine calls with their Embedder API equivalents behind `--android-embedder-api`.
The first call replacement is:
```
platform_view_->DispatchPointerDataPacket(...) -> FlutterEngineSendPointerEvent
```

Requirements for all Stage 3 tasks:
1. Flagged: Legacy path remains 100% intact and reachable when `--android-embedder-api` is off.
2. The branch point carries `TRACE_EVENT` with the resolved path (`embedder_api` vs `legacy`).
3. Once migrated behind the flag, `platform_view_` usage is not dual-routed on the flag-on path.
4. Parity tests verify both flag states.

## Decision
1. Add `SendPointerEvents(const FlutterPointerEvent* events, size_t count)` to `PlatformViewAndroid`, matching the C-ABI `FlutterEngineSendPointerEvent` signature and returning `FlutterEngineResult`.
2. In `PlatformViewAndroid::DispatchPointerDataPacket`:
   - If `android_embedder_api_` is true:
     Convert incoming packet to `FlutterPointerEvent` array and dispatch through `SendPointerEvents`, emitting `TRACE_EVENT1("flutter", "PlatformViewAndroid::DispatchPointerDataPacket", "path", "embedder_api")`.
   - If `android_embedder_api_` is false:
     Forward directly to `platform_view_->DispatchPointerDataPacket(std::move(packet))`, emitting `TRACE_EVENT1("flutter", "PlatformViewAndroid::DispatchPointerDataPacket", "path", "legacy")`.
3. Add unit tests in `platform_view_android_unittests.cc` asserting:
   - Flag off invokes `platform_view_->DispatchPointerDataPacket`.
   - Flag on routes exclusively through `SendPointerEvents` without touching `platform_view_` (no dual routing).
   - Direct `SendPointerEvents` argument validation (`kInvalidArguments` on null/zero, `kSuccess` on valid).

## Consequences
- Pointer event handling conforms to the `FlutterEngineSendPointerEvent` C-ABI shape.
- Strict isolation between flag states; zero regression risk with flag off.
- Dependency ratchet remains <= baseline.

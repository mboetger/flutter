## Context
`MIGRATION_LEDGER.md` §T-0.5 tasked us with evaluating candidate vestigial configurations (`kSoftware`, `kSkiaOpenGLES`, `kImpellerAutoselect`, `kMergeAfterLaunch`) in `AndroidRenderingAPI` (`shell/platform/android/android_rendering_selector.h:11`) for deletion to reduce migration surface area. The instruction mandates removing only configurations whose analysis proves they are unreachable or formally unsupported, and explicitly forbids removing configurations whose analysis is inconclusive or that would violate invariants.

## Options considered
| # | Option | Consequence |
|---|---|---|
| A | Delete `kSoftware` and `kSkiaOpenGLES` immediately on T-0.5 | Violates Invariant I-1 (No silent fallbacks). Breaks Flutter apps running on Android API 21–28 (which fall back to `kSkiaOpenGLES`), breaks devices with Vivante GPUs, and breaks test harnesses relying on `--enable-software-rendering`. |
| B | Retain configurations; document reachability, dependencies, and retirement milestones in `embedder_test_gaps.md` | Preserves 100% backwards compatibility and testing capabilities. Provides explicit tracking criteria for when Flutter upstream raises `minSdkVersion` to 29 or completes Impeller opt-out deprecation. |

## Tie-break
Criterion 1 & 4 from `MIGRATION_PLAN.md` §10.1:
- Criterion 1: Preserves runtime behaviour and backward compatibility for existing Flutter apps on Android API 21–28 and test harnesses.
- Criterion 4: Prevents silent crashes or missing fallbacks when older devices run Flutter.

## Decision
Zero rendering configurations are deleted in task T-0.5. `kSoftware` is retained for testing harnesses and headless emulators; `kSkiaOpenGLES` is retained for Android API 21–28 and Vivante GPUs; `kImpellerAutoselect` is retained as the production engine default; and `kMergeAfterLaunch` is preserved on the engine-switch route. Complete reachability analyses and retirement conditions are documented in `engine/src/flutter/docs/android/embedder_test_gaps.md`.

## What would change this decision
Flutter upstream formally raising the minimum supported Android API level to 29 (`minSdkVersion >= 29`) and removing the `--no-enable-impeller` opt-out flag across the engine, which would render `kSkiaOpenGLES` completely unreachable in production.

## Evidence
- `shell/platform/android/flutter_main.cc:294-299`:
  ```cpp
  if (settings.enable_impeller &&
      api_level >= kMinimumAndroidApiLevelForImpeller && !IsVivante()) {
    return AndroidRenderingAPI::kImpellerAutoselect;
  }
  return AndroidRenderingAPI::kSkiaOpenGLES;
  ```
- `shell/platform/android/io/flutter/embedding/engine/FlutterShellArgs.java:44`:
  `ARG_ENABLE_SOFTWARE_RENDERING` is exposed as public CLI argument and used in `FlutterActivityTestRule.java`.

## Consequences
Downstream migration tasks (Stage 2 and Stage 3) must continue to account for the existence of `kSkiaOpenGLES` and `kSoftware` in `AndroidRenderingAPI` (or isolate them under `!SLIMPELLER` build gates) until upstream platform milestones are reached.

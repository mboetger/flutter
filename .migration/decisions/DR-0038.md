# DR-0038: Introduce a Compositor Seam in front of AndroidExternalViewEmbedderWrapper Shaped like FlutterCompositor

- **Status:** Accepted
- **Task:** T-2.9
- **Date:** 2026-09-16
- **Context:** Advancing Stage 2 (Refactoring & Decoupling) per `MIGRATION_LEDGER.md` §Stage 2 by introducing a compositor seam (`AndroidCompositorAdapter`) shaped like `FlutterCompositor` in front of `AndroidExternalViewEmbedderWrapper`.

---

## 1. Problem Statement
In the legacy Android embedder, platform view composition is managed through `AndroidExternalViewEmbedderWrapper`:
- Dynamically selects between `AndroidExternalViewEmbedder` (HC, VD, TLHC) and `AndroidExternalViewEmbedder2` (HCPP).
- Implements the engine internal `ExternalViewEmbedder` interface.

In Stage 3, composition will be delegated to the Embedder API's `FlutterCompositor` mechanism:
- `create_backing_store_callback`
- `collect_backing_store_callback`
- `present_view_callback`
- `supports_dynamic_thread_merging` (from T-0.13)
- `post_preroll_callback`
- `begin_frame_callback`
- `end_frame_callback`

In previous migration attempts (v7), platform view files were deleted and the compositor was disconnected (`grep -c FlutterCompositor` was 0), breaking platform views across Android.
To prepare for Stage 3 while preserving 100% behavioral equivalence across all composition modes in Stage 2:
- Introduce `AndroidCompositorAdapter` in front of `AndroidExternalViewEmbedderWrapper`.
- `AndroidCompositorAdapter` implements `ExternalViewEmbedder` by forwarding all calls directly to `AndroidExternalViewEmbedderWrapper`.
- `AndroidCompositorAdapter` constructs and exposes the `FlutterCompositor` C-ABI struct shape.
- `PlatformViewAndroid::CreateExternalViewEmbedder()` returns `AndroidCompositorAdapter` wrapping `AndroidExternalViewEmbedderWrapper`.
- Zero files under `external_view_embedder/` are deleted (I-11).
- Ratchet counts must remain `<= baseline` (deps <= 63, includes <= 121, nogncheck == 0).

---

## 2. Technical Solution

1. **`AndroidCompositorAdapter` Class:**
   - Lives in `shell/platform/android/android_compositor_adapter.{h,cc}`.
   - Wraps `std::shared_ptr<AndroidExternalViewEmbedderWrapper> view_embedder_wrapper_`.
   - Inherits from `ExternalViewEmbedder`, delegating all methods:
     - `PrerollCompositeEmbeddedView`
     - `CompositeEmbeddedView`
     - `SubmitFlutterView`
     - `PostPrerollAction`
     - `GetRootCanvas`
     - `BeginFrame`
     - `PrepareFlutterView`
     - `CancelFrame`
     - `EndFrame`
     - `SupportsDynamicThreadMerging`
     - `Teardown`
   - Populates and exposes `const FlutterCompositor* GetFlutterCompositor() const`.
   - Provides static callback trampolines for `FlutterCompositor`:
     - `create_backing_store_callback`
     - `collect_backing_store_callback`
     - `present_view_callback`
     - `post_preroll_callback`
     - `begin_frame_callback`
     - `end_frame_callback`

2. **Integration into `PlatformViewAndroid`:**
   - In `PlatformViewAndroid::CreateExternalViewEmbedder()`:
     ```cpp
     auto view_embedder = std::make_shared<AndroidExternalViewEmbedderWrapper>(
         android_meets_hcpp_criteria_, *android_context_, jni_facade_,
         surface_factory_, task_runners_);
     return std::make_shared<AndroidCompositorAdapter>(std::move(view_embedder));
     ```
   - All external callers and characterization tests interact with `ExternalViewEmbedder` as before.

3. **Dependency and Ratchet Impact:**
   - Added to `flutter_shell_native_src` in `shell/platform/android/BUILD.gn`.
   - Headers: `flutter/shell/platform/android/external_view_embedder/external_view_embedder_wrapper.h`, `flutter/shell/platform/embedder/embedder.h`, `flutter/flow/embedded_views.h`.
   - Allowed in `ALLOWED_HEADER_PREFIXES`.
   - Net internal includes change: 0.
   - Net internal deps change: 0.
   - Zero nogncheck.

4. **Testing:**
   - Add unit tests in `android_compositor_adapter_unittests.cc` (or `platform_view_android_unittests.cc`):
     - Validates `FlutterCompositor` struct size, callbacks, and `supports_dynamic_thread_merging`.
     - Validates transparent forwarding of all `ExternalViewEmbedder` calls to the underlying wrapper.
   - Retain all existing unit and characterization tests unmodified.

# DR-0033: Break PlatformViewAndroid : PlatformView Inheritance

- **Status:** Accepted
- **Task:** T-2.4
- **Date:** 2026-09-16
- **Context:** Advancing Stage 2 (Refactoring & Decoupling) per `MIGRATION_LEDGER.md` §Stage 2 by severing the `PlatformViewAndroid : PlatformView` inheritance hierarchy.

---

## 1. Problem Statement
In Stage 2:
- T-2.1 introduced the `platform_view_` delegate pointer seam on `PlatformViewAndroid`.
- T-2.2 (a, b, c) migrated all virtual overrides on `PlatformViewAndroid` to forward across the `platform_view_` seam.
- T-2.3 constructed `PlatformViewEmbedder` in `AndroidShellHolder` and wired `PlatformViewAndroid::SetPlatformView`.
- T-2.4 breaks the `PlatformViewAndroid : PlatformView` inheritance.

Governing invariant: Stage 2 changes NO behavior. All Stage 0 characterization tests must pass unmodified. No `FlutterEngine*` calls are introduced in Stage 2. Ratchets must remain `<= baseline`.

---

## 2. Technical Solution

1. **Severing the Inheritance:**
   - Remove `: public PlatformView` from `PlatformViewAndroid`.
   - `PlatformViewAndroid` becomes a standalone Android platform class.
   - Remove `override` specifiers on methods that were previously `PlatformView` virtual overrides.
   - Remove unused/redundant virtual methods that are handled entirely by `PlatformViewEmbedder` (e.g., `UpdateAssetResolverByType`, `LoadDartDeferredLibrary`, `LoadDartDeferredLibraryError`).

2. **Ownership and Shell Callback:**
   - In `AndroidShellHolder::AndroidShellHolder` and `Spawn`, `on_create_platform_view` now returns `platform_view_embedder` (`std::unique_ptr<PlatformView>`).
   - `AndroidShellHolder` owns `platform_view_android_` as `std::unique_ptr<PlatformViewAndroid>`.
   - `PlatformViewAndroid` retains its pointer to `platform_view_` (`PlatformView*`), allowing it to invoke engine delegation methods (`DispatchPlatformMessage`, `DispatchPointerDataPacket`, `SetViewportMetrics`, `DispatchSemanticsAction`, `SetSemanticsEnabled`, `UnregisterTexture`, `MarkTextureFrameAvailable`, `NotifyDestroyed`).

3. **Dependency and Include Ratchet:**
   - In `platform_view_android.h`, forward-declare `class PlatformView;` instead of requiring full inheritance.
   - Internal dependencies remain at 26 (baseline 26).
   - Internal includes remain `<= 98` (baseline 98).
   - Zero `nogncheck`.

4. **Testing and Verification:**
   - All characterization unit tests and shell holder unit tests verify that `PlatformViewAndroid` interacts with `PlatformViewEmbedder` seamlessly.
   - Verified that `GetPlatformView()` returns `fml::WeakPtr<PlatformViewAndroid>`.

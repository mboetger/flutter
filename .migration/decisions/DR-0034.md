# DR-0034: Extract Thread Configuration into Standalone Unit Matching FlutterCustomTaskRunners Shape

- **Status:** Accepted
- **Task:** T-2.5
- **Date:** 2026-09-16
- **Context:** Advancing Stage 2 (Refactoring & Decoupling) per `MIGRATION_LEDGER.md` §Stage 2 by extracting thread configuration from `AndroidShellHolder` into a standalone unit matching `FlutterCustomTaskRunners` shape.

---

## 1. Problem Statement
In `AndroidShellHolder`, thread configuration and task runner resolution are currently embedded directly in the constructor:
- Thread labeling and thread mask computation based on `settings.merged_platform_ui_thread`.
- `AndroidPlatformThreadConfigSetter` setting POSIX thread priorities (`-1` UI, `-5` Raster with `-2` fallback, `0` IO, `0` Platform/Worker) and CPU affinities.
- Creating the `flutter::ThreadHost` and resolving `flutter::TaskRunners` (platform, raster, ui, io).
- In `Spawn()`, sharing the existing `thread_host_`.

To prepare for `FlutterProjectArgs` construction in T-2.8 and eventual Embedder API migration in Stage 3, thread management must be decoupled into a dedicated unit (`AndroidTaskRunners`) that provides both:
1. The internal `flutter::TaskRunners` needed by `Shell` during Stage 2.
2. The `FlutterCustomTaskRunners` structure (and `FlutterThreadPrioritySetter` callback) matching the public Embedder API contract established in T-1.12.

Governing invariants:
- Stage 2 changes NO behavior. All Stage 0 characterization tests (specifically `android_threading_unittests.cc`) must pass unmodified.
- No `FlutterEngine*` calls are introduced in Stage 2. Shapes only.
- Ratchet counts must remain `<= baseline` (deps <= 63, includes <= 123, nogncheck == 0).

---

## 2. Technical Solution

1. **Standalone Unit (`AndroidTaskRunners`):**
   - Create `android_task_runners.h` and `android_task_runners.cc` in `shell/platform/android`.
   - `AndroidTaskRunners` encapsulates:
     - Thread creation via `flutter::ThreadHost`.
     - Priority setting via `AndroidPlatformThreadPrioritySetter(FlutterThreadPriority priority)` matching `FlutterThreadPrioritySetter`.
     - Adapter `AndroidPlatformThreadConfigSetter(const fml::Thread::ThreadConfig& config)` for `fml::Thread`.
     - Task runner resolution: `task_runners_` (`flutter::TaskRunners`).
     - Embedder API representation: `custom_task_runners_` (`FlutterCustomTaskRunners`) with `io_thread_priority = FlutterThreadPriority::kNormal`.
   - Expose:
     - `const flutter::TaskRunners& GetTaskRunners() const`
     - `const FlutterCustomTaskRunners* GetCustomTaskRunners() const`
     - `std::shared_ptr<ThreadHost> GetThreadHost() const`
     - `static std::unique_ptr<AndroidTaskRunners> Create(const std::string& thread_label, const Settings& settings)`

2. **Integration into `AndroidShellHolder`:**
   - Replace direct `thread_host_` ownership with `std::shared_ptr<AndroidTaskRunners> task_runners_`.
   - In constructor, delegate thread creation to `AndroidTaskRunners::Create(...)`.
   - In `Spawn()`, reuse `task_runners_` (or spawn from it with shared thread host).
   - Remove `#include "flutter/shell/common/thread_host.h"` from `android_shell_holder.h` and `android_shell_holder.cc`.

3. **Dependency and Ratchet Impact:**
   - `android_task_runners.h` includes only allowed headers (`flutter/common/task_runners.h`, `flutter/shell/platform/embedder/embedder.h`). Zero internal includes.
   - `android_task_runners.cc` includes `flutter/shell/common/thread_host.h` (+1 internal include).
   - `android_shell_holder.h` and `android_shell_holder.cc` remove `flutter/shell/common/thread_host.h` (-2 internal includes).
   - Net internal includes change: -1. Total includes decrease to 121 (well below 123 baseline).
   - Internal dependencies remain 26 (baseline 26).
   - Zero nogncheck.

4. **Testing:**
   - Add unit tests in `android_threading_unittests.cc` verifying `AndroidTaskRunners` and its `FlutterCustomTaskRunners` structure and priority setter.
   - Verify that all characterization tests in `android_threading_unittests.cc` pass unmodified.

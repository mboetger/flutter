# DR-0039: Introduce an External Texture Seam in front of SurfaceTextureExternalTexture and ImageExternalTexture

- **Status:** Accepted
- **Task:** T-2.10
- **Date:** 2026-09-16
- **Context:** Advancing Stage 2 (Refactoring & Decoupling) per `MIGRATION_LEDGER.md` §Stage 2 by introducing an external texture seam (`AndroidExternalTextureAdapter`) shaped like `FlutterEngineRegisterExternalTexture`.

---

## 1. Problem Statement
In the legacy Android embedder, external texture management (used by Virtual Displays, Texture Layer Hybrid Composition, and media plugins such as video player and camera) is divided across two base classes and six concrete implementations:
- `SurfaceTextureExternalTexture` (`SurfaceTextureExternalTextureGLSkia`, `SurfaceTextureExternalTextureGLImpeller`, `SurfaceTextureExternalTextureVKImpeller`)
- `ImageExternalTexture` (`ImageExternalTextureGLSkia`, `ImageExternalTextureGLImpeller`, `ImageExternalTextureVKImpeller`)

In previous migration attempts (v7), both external texture implementations were deleted and replaced with a dummy map insert, silently breaking VD, TLHC, and all external texture media plugins across Android.

To prepare for Stage 3 while preserving 100% behavioral equivalence across all rendering backends in Stage 2:
- Introduce an external texture seam (`AndroidExternalTextureAdapter`) in front of `SurfaceTextureExternalTexture` and `ImageExternalTexture`.
- Shape the seam like the Embedder API's texture management functions:
  - `RegisterExternalTexture(int64_t texture_identifier)`
  - `UnregisterExternalTexture(int64_t texture_identifier)`
  - `MarkExternalTextureFrameAvailable(int64_t texture_identifier)`
- Support both the legacy Android JNI registration paths (`RegisterSurfaceTexture`, `RegisterImageTexture`) and the Embedder API registration shape.
- Zero files under `external_view_embedder/` are deleted (I-11).
- Neither `SurfaceTextureExternalTexture` nor `ImageExternalTexture` is deleted (I-11).
- Ratchet counts must remain `<= baseline` (deps <= 63, includes <= 121, nogncheck == 0).

---

## 2. Technical Solution

1. **`AndroidExternalTextureAdapter` Class:**
   - Lives in `shell/platform/android/android_external_texture_adapter.{h,cc}`.
   - Encapsulates:
     - `const AndroidContext& android_context_`
     - `std::shared_ptr<PlatformViewAndroidJNI> jni_facade_`
     - `Delegate* delegate_`
   - Defines a `Delegate` interface:
     ```cpp
     class Delegate {
      public:
       virtual ~Delegate() = default;
       virtual void OnRegisterTexture(std::shared_ptr<flutter::Texture> texture) = 0;
       virtual void OnUnregisterTexture(int64_t texture_id) = 0;
       virtual void OnMarkTextureFrameAvailable(int64_t texture_id) = 0;
     };
     ```
   - Legacy Android registration methods:
     - `bool RegisterSurfaceTexture(int64_t texture_id, const fml::jni::ScopedJavaGlobalRef<jobject>& surface_texture)`
     - `bool RegisterImageTexture(int64_t texture_id, const fml::jni::ScopedJavaGlobalRef<jobject>& image_texture_entry, ImageExternalTexture::ImageLifecycle lifecycle)`
     - Dynamically selects the appropriate backend subclass (`GLSkia`, `GLImpeller`, `VKImpeller`) based on `android_context_.RenderingApi()` and notifies the delegate.
   - Embedder API shaped methods:
     - `FlutterEngineResult RegisterExternalTexture(int64_t texture_identifier)`
     - `FlutterEngineResult UnregisterExternalTexture(int64_t texture_identifier)`
     - `FlutterEngineResult MarkExternalTextureFrameAvailable(int64_t texture_identifier)`
   - Texture registry query methods:
     - `bool HasTexture(int64_t texture_id) const`
     - `std::shared_ptr<flutter::Texture> GetTexture(int64_t texture_id) const`
     - `size_t TextureCount() const`

2. **Integration into `PlatformViewAndroid`:**
   - `PlatformViewAndroid` implements `AndroidExternalTextureAdapter::Delegate`.
   - `PlatformViewAndroid` owns `std::unique_ptr<AndroidExternalTextureAdapter> external_texture_adapter_`.
   - In `RegisterExternalTexture(...)`, delegates to `external_texture_adapter_->RegisterSurfaceTexture(...)`.
   - In `RegisterImageTexture(...)`, delegates to `external_texture_adapter_->RegisterImageTexture(...)`.
   - In `UnregisterTexture(int64_t id)`, delegates to `external_texture_adapter_->UnregisterExternalTexture(id)`.
   - In `MarkTextureFrameAvailable(int64_t id)`, delegates to `external_texture_adapter_->MarkExternalTextureFrameAvailable(id)`.
   - Exposes testing accessor: `AndroidExternalTextureAdapter* GetExternalTextureAdapterForTesting() const`.

3. **Dependency and Ratchet Impact:**
   - Headers: `flutter/common/graphics/texture.h`, `flutter/shell/platform/android/...`, `flutter/shell/platform/embedder/embedder.h`.
   - All within `ALLOWED_HEADER_PREFIXES`.
   - Net internal includes change: 0.
   - Net internal deps change: 0.
   - Zero nogncheck.

4. **Testing:**
   - Dedicated unit tests in `android_external_texture_adapter_unittests.cc`:
     - Test `EmbedderApiShapeRegistration`: verifies `RegisterExternalTexture`, `UnregisterExternalTexture`, and `MarkExternalTextureFrameAvailable` handle valid IDs and error conditions.
     - Test `SurfaceTextureRegistration`: verifies proper `flutter::Texture` instantiation across rendering APIs.
     - Test `ImageTextureRegistration`: verifies proper `ImageExternalTexture` instantiation and lifecycle tracking.
     - Test `PlatformViewAndroidWiring`: verifies delegate callbacks and testing accessors on `PlatformViewAndroid`.

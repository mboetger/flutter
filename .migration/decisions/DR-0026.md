# DR-0026: EmbedderExternalViewEmbedder Dynamic Thread Merging Implementation

- **Status:** Accepted
- **Task:** T-1.18b
- **Date:** 2026-09-16
- **Context:** Implementing dynamic thread merging overrides in `EmbedderExternalViewEmbedder` and wiring `FlutterCompositor` dynamic thread merging configuration in `embedder.cc` to unblock Hybrid Composition (HC) on Android.

---

## 1. Problem Statement
In T-1.18a, the public C-ABI types and proc table functions for dynamic raster thread merging were added to `embedder.h` and `embedder.cc`. However, `EmbedderExternalViewEmbedder` does not yet override `SupportsDynamicThreadMerging()`, `PostPrerollAction()`, `BeginFrame()`, or `EndFrame()`. Without these overrides:
1. `Rasterizer::Setup` never creates a `RasterThreadMerger` when an embedder configures `supports_dynamic_thread_merging = true`.
2. When preroll completes, the embedder's `post_preroll_callback` is never invoked, preventing lease requests or frame resubmissions.
3. Frame lifecycle notifications (`begin_frame_callback` / `end_frame_callback`) are never dispatched to the embedder.

---

## 2. Technical Solution
1. **Shared Merger Struct:**
   Define `struct _FlutterRasterThreadMerger { fml::RefPtr<fml::RasterThreadMerger> merger; };` in `embedder_external_view_embedder.h` so both `embedder.cc` and `embedder_external_view_embedder.cc` share the identical layout.

2. **`EmbedderExternalViewEmbedder` Overrides:**
   - Extend constructor to accept `supports_dynamic_thread_merging`, `post_preroll_callback`, `begin_frame_callback`, `end_frame_callback`, and `user_data`.
   - `SupportsDynamicThreadMerging()` returns `supports_dynamic_thread_merging_`.
   - `PostPrerollAction(merger)`: Wraps `raster_thread_merger` into `FlutterFrameThreadingInfo` and executes `post_preroll_callback`, mapping `FlutterPostPrerollResult` to `PostPrerollResult`.
   - `BeginFrame(context, merger)`: Calls `Reset()`, wraps merger into `FlutterFrameThreadingInfo`, and executes `begin_frame_callback`.
   - `EndFrame(should_resubmit, merger)`: Wraps merger into `FlutterFrameThreadingInfo` and executes `end_frame_callback`.

3. **`embedder.cc` Wiring (`InferExternalViewEmbedderFromArgs`):**
   - Extract `supports_dynamic_thread_merging`, `post_preroll_callback`, `begin_frame_callback`, and `end_frame_callback` via `SAFE_ACCESS`.
   - Validate invariant I-1: if `supports_dynamic_thread_merging` is true and `post_preroll_callback` is null, abort initialization with `kInvalidArgument`.
   - Forward configuration to `EmbedderExternalViewEmbedder`.

---

## 3. Invariants & Safety
- **I-1 No silent fallbacks:** Missing required `post_preroll_callback` when dynamic merging is requested immediately fails initialization.
- **Inertness:** Zero-initialization ensures `supports_dynamic_thread_merging = false` for all existing desktop/iOS embedders.
- **Diff cap:** Within standard refactor/addition limits.

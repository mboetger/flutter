# DR-0021 — Enum Representation for Platform Message Routing in Embedder API

- **Task:** T-1.13
- **Branch:** `android-embedder-v8/t-1.13-background-platform-channels`
- **Author role:** planner
- **Date:** 2026-09-16
- **Status:** accepted
- **Confidence:** firm

## Context
In Task T-1.13 (Blocker B-3, DR-0020), the Embedder API is extended to allow embedders to receive platform messages directly on the engine calling thread (UI task runner) rather than always hopping through the platform task runner.
The API knob needs to specify routing behavior in `FlutterProjectArgs`.

## Options considered
1. **Option 1: Plain boolean `does_handle_platform_messages_on_platform_thread`**
   - In C, zero-initialization fills all fields with 0 (`false`).
   - If `false` meant "direct/calling thread", any embedder recompiling with zero-initialization would silently have its message routing changed, breaking desktop embedders.
   - If `false` meant "platform thread", the name would be confusingly inverted relative to `PlatformMessageHandler::DoesHandlePlatformMessageOnPlatformThread()`.
2. **Option 2: Plain boolean `direct_platform_message_handling`**
   - `0` (`false`) naturally means "not direct" (default platform thread routing).
   - Works, but is binary and cannot express future routing models (such as dedicated worker queues or isolate-specific ports).
3. **Option 3: Enum `FlutterPlatformMessageRouting`**
   - `kFlutterPlatformMessageRoutingPlatformThread = 0`: Safe, unambiguous default for zero-initialized memory and truncated legacy structs.
   - `kFlutterPlatformMessageRoutingCallingThread = 1`: Clear, self-documenting opt-in for direct engine calling thread delivery.
   - Future-proof and extensible.

## Tie-break (§10.1)
- **Criterion 1 (Preserves observable behaviour exactly):** Option 3 guarantees that zero-initialized structs strictly preserve the legacy platform thread routing behavior.
- **Criterion 4 (Fails loudly rather than degrading silently):** Option 3 makes the routing mode explicit and self-documenting.
- **Criterion 6 (Narrower API surface):** Minimal additive enum and single struct field in `FlutterProjectArgs`.

## Decision
Adopt Option 3 (`FlutterPlatformMessageRouting`).

## What would change this decision
If the Embedder API transitions entirely to a callback registration model with per-channel routing handlers.

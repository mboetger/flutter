# DR-0036: Extract Surface Lifecycle into the Shape Decided by T-0.7

- **Status:** Accepted
- **Task:** T-2.7
- **Date:** 2026-09-16
- **Context:** Advancing Stage 2 (Refactoring & Decoupling) per `MIGRATION_LEDGER.md` §Stage 2 by extracting surface lifecycle from `PlatformViewAndroid` into the shape decided by T-0.7 and T-1.2.

---

## 1. Problem Statement
In `PlatformViewAndroid`, surface lifecycle management is tightly coupled with general platform view dispatching:
- `NotifyCreated`, `NotifySurfaceWindowChanged`, and `NotifyDestroyed` directly manage raster-thread synchronization with `AndroidSurface` (`SetNativeWindow`, `TeardownOnScreenContext`) using synchronous waitable latches (`fml::AutoResetWaitableEvent`).
- They also drive first-frame callback installation (`InstallFirstFrameCallback`) and frame scheduling (`ScheduleFrame`).
- In T-0.7 and T-1.2, the Embedder API established the canonical surface and renderer availability lifecycle:
  - `FlutterEngineNotifySurfaceCreated(engine, view_id)`
  - `FlutterEngineNotifySurfaceDestroyed(engine, view_id)`
  - `FlutterEngineSetGpuAvailability(engine, availability)` using `FlutterGpuAvailability`.

To prepare for Stage 3 Embedder API calls while maintaining 100% behavioral equivalence in Stage 2:
- Surface lifecycle and raster-thread synchronization must be decoupled into a dedicated unit (`AndroidSurfaceLifecycle`).
- The unit must reflect the lifecycle semantics from T-0.7 (`NotifySurfaceCreated`, `NotifySurfaceDestroyed`, `SetGpuAvailability`).
- All Stage 0 characterization tests (`platform_view_android_surface_lifecycle_unittests.cc`) must pass completely unmodified.
- Ratchet counts must remain `<= baseline` (deps <= 63, includes <= 123, nogncheck == 0).

---

## 2. Technical Solution

1. **Standalone Unit (`AndroidSurfaceLifecycle`):**
   - Create `android_surface_lifecycle.h` and `android_surface_lifecycle.cc` in `shell/platform/android`.
   - `AndroidSurfaceLifecycle` encapsulates:
     - Raster thread synchronization for attaching and detaching `AndroidNativeWindow`.
     - First-frame callback installation on `NotifyCreated`.
     - Context teardown on `NotifySurfaceWindowChanged` and `NotifyDestroyed`.
     - Dynamic GPU availability state management (`SetGpuAvailability`) matching `FlutterGpuAvailability` (`kAvailable`, `kFlushAndMakeUnavailable`, `kUnavailable`).
     - Tracking surface availability (`IsSurfaceAvailable()`).
   - Delegates engine notifications (`on_surface_created`, `on_surface_destroyed`, `on_schedule_frame`, `set_next_frame_callback`) back to the platform view delegate.

2. **Integration into `PlatformViewAndroid`:**
   - `PlatformViewAndroid` owns `std::unique_ptr<AndroidSurfaceLifecycle> surface_lifecycle_`.
   - `NotifyCreated`, `NotifySurfaceWindowChanged`, and `NotifyDestroyed` forward to `surface_lifecycle_`.
   - Add `SetGpuAvailability(FlutterGpuAvailability availability)` forwarding to `surface_lifecycle_`.
   - Expose `AndroidSurfaceLifecycle* GetSurfaceLifecycleForTesting() const`.

3. **Dependency and Ratchet Impact:**
   - All includes in `android_surface_lifecycle.{h,cc}` are from allowed prefixes (`flutter/fml/`, `flutter/common/`, `flutter/shell/platform/embedder/embedder.h`, `flutter/shell/platform/android/`).
   - Net internal includes change: 0.
   - Net internal deps change: 0.
   - Zero nogncheck.

4. **Testing:**
   - All Stage 0 characterization tests in `platform_view_android_surface_lifecycle_unittests.cc` pass unmodified.
   - Add unit tests verifying `AndroidSurfaceLifecycle` directly:
     - `NotifyCreated` sets surface availability and attaches window.
     - `NotifyDestroyed` clears surface availability and tears down on-screen context.
     - `SetGpuAvailability` transitions (`kAvailable`, `kFlushAndMakeUnavailable`, `kUnavailable`).
     - Idempotent double create and double destroy.

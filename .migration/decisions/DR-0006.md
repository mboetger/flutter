# DR-0006
**Status:** superseded by DR-0012
: Comprehensive Dependency Injection to Prevent Sandbox Escapes

**Date:** 2026-09-15
**Task:** T-0.15a
**Status:** Active (Supersedes DR-0005)

## Context
DR-0005 introduced `GateExecutor` to prevent tests from executing real, multi-hour gates. However, review revealed this was insufficient: tests would still execute real `git status` and `git rev-parse` operations, creating incentives to sabotage uncommitted files in the repository. Furthermore, verifying pipeline files (`--check-artifact-sha`) against the real disk incentivized implementers to spoof environments or delete real requirement files.

## Decision
1. **Total Process Virtualization:** Expand the DI interface from `GateExecutor` to a generalized `SystemCommandExecutor`. ALL subprocess executions, including Git operations, must be intercepted. Tests will use `FakeSystemCommandExecutor` exclusively.
2. **Total Filesystem Virtualization:** Mandate the use of `package:file/memory.dart` (`MemoryFileSystem`) to mock all disk access in unit tests.
3. **No Backdoors:** Banned any environment variable or CLI parameter overrides for validation directory paths. Production execution unconditionally targets the physical repository root, while tests exclusively evaluate the in-memory filesystem.
4. **Threat Model Reality:** The tool's telemetry cannot prevent an implementer from modifying the tool itself or replacing a target script with `sleep 3600; exit 0`. Mechanical spoof detection relies exclusively on the Code Reviewer catching modifications to the tool, and post-facto telemetry analysis of standard execution profiles.

# DR-0008
**Status:** superseded by DR-0012
: Architecturally Decoupling Expensive Mocks to Maintain I-4 Parity

**Date:** 2026-09-15
**Task:** T-0.15a / T-0.15b
**Status:** Active (Supersedes DR-0007)

## Context
DR-0007 delegated testing for `--audit-stack` and `--device-lock` to the Validator to avoid prohibitively expensive virtualization mock setups. Review rightly identified this violated I-4 (tests failing before and passing after) because an implementer could pass the unit test suite with empty function stubs for T-0.15b. Furthermore, it established a toxic precedent that testing rigor can be deferred when inconvenient.

## Decision
1. **Reinstatement of Tests**: Both `--audit-stack` and `--device-lock` unit tests are reinstated.
2. **Decoupling Data Retrieval (Audit Stack)**: To prevent expensive stateful mocking, logic must be refactored into pure functions. `validateStack` will accept `v(List<String> mockGitLog, FileSystem fs)` instead of forcing the test to wire an elaborate `FakeSystemCommandExecutor`.
3. **Narrow Exemption for Hardware Locks**: Because `MemoryFileSystem` cannot share file-locks across `Isolate.run()` boundaries, `--device-lock` tests receive a narrow, explicit exception allowing physical use of `Directory.systemTemp`. The lock test is strictly banned from touching `.migration/` directories or navigating into the real repository root.

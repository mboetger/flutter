# DR-0037: Restructure AndroidShellHolder toward FlutterProjectArgs Construction

- **Status:** Accepted
- **Task:** T-2.8
- **Date:** 2026-09-16
- **Context:** Advancing Stage 2 (Refactoring & Decoupling) per `MIGRATION_LEDGER.md` §Stage 2 by restructuring `AndroidShellHolder` to construct and maintain `FlutterProjectArgs` in preparation for Stage 3 engine initialization via the Embedder API.

---

## 1. Problem Statement
`AndroidShellHolder` is the central C++ orchestrator for the Android embedding. It manages:
- Thread creation and configuration (extracted into `AndroidTaskRunners` in T-2.5).
- Asset resolution (extracted into `APKAssetProvider` in T-2.6).
- Platform view and embedder dispatching (refactored in T-2.1-T-2.4).
- Surface lifecycle management (extracted into `AndroidSurfaceLifecycle` in T-2.7).

Currently, `AndroidShellHolder` instantiates the engine via `Shell::Create(...)` and runs it via `shell_->RunEngine(...)`.
In Stage 3 (Adherence), `AndroidShellHolder` will initialize and run the engine using the Embedder API entrypoints:
`FlutterEngineInitialize(FLUTTER_ENGINE_VERSION, &renderer_config, &project_args, user_data, &engine);`
`FlutterEngineRunInitialized(engine);`

`FlutterEngineInitialize` takes `const FlutterProjectArgs* args`, which aggregates custom task runners, asset resolvers, platform callbacks, and engine flags.
To prepare for Stage 3 while preserving 100% behavioral equivalence in Stage 2:
- `AndroidShellHolder` must be restructured to construct the `FlutterProjectArgs` structure from its components (`AndroidTaskRunners`, `APKAssetProvider`, `Settings`, and `PlatformViewAndroidJNI`).
- `AndroidShellHolder` must expose `CreateFlutterProjectArgs(...)` and `GetProjectArgsForTesting()` so unit tests can assert and validate the populated `FlutterProjectArgs` struct shape against ground truth.
- `Shell::Create` and existing Stage 2 behavior remain 100% active and unmodified.
- Ratchet counts must remain `<= baseline` (deps <= 63, includes <= 121, nogncheck == 0).

---

## 2. Technical Solution

1. **`FlutterProjectArgs` Construction in `AndroidShellHolder`:**
   - Add `#include "flutter/shell/platform/embedder/embedder.h"` to `android_shell_holder.h` (allowed in `tools/android_embedder_deps.py`).
   - Store member `FlutterProjectArgs project_args_ = {};` and backing storage (e.g., `const FlutterAssetResolver* asset_resolvers_[1];`, `std::vector<const char*> command_line_argv_`).
   - In constructor and `UpdateProjectArgs()`:
     - Populate `struct_size = sizeof(FlutterProjectArgs)`.
     - Bind `custom_task_runners = task_runners_->GetCustomTaskRunners();` (from T-2.5).
     - Bind `icu_data_path = settings_.icu_data_path.c_str();`.
     - Bind `assets_path = settings_.assets_path.c_str();`.
     - Bind command line arguments from `settings_.command_line_args`.
     - Bind C-ABI callbacks forwarding to `jni_facade_`:
       - `on_pre_engine_restart_callback`
       - `set_application_locale_callback`
       - `get_scaled_font_size_callback`
       - `dart_deferred_library_request_callback`
   - In `Launch(...)` and `Spawn(...)`:
     - Bind `apk_asset_provider_->GetFlutterAssetResolver()` into `asset_resolvers_[0]`.
     - Set `asset_resolvers_count = 1`.
     - Set `engine_id = engine_id`.

2. **Testing & Verification:**
   - Expose `const FlutterProjectArgs* GetProjectArgsForTesting() const;`.
   - Expose `FlutterProjectArgs CreateFlutterProjectArgs(...) const;`.
   - Add unit tests in `android_shell_holder_unittests.cc`:
     - Validate `FlutterProjectArgs` struct integrity (`struct_size`, `custom_task_runners`, callbacks).
     - Validate asset resolver integration in `FlutterProjectArgs`.
     - Validate callback execution forwarding through `jni_facade_`.
   - Retain all existing tests unmodified.

3. **Dependency and Ratchet Impact:**
   - All includes are from allowed prefixes (`flutter/fml/`, `flutter/shell/platform/embedder/embedder.h`, `flutter/shell/platform/android/`).
   - Net internal includes change: 0.
   - Net internal deps change: 0.
   - Zero nogncheck.

# Context: T-2.9 — Introduce a Compositor Seam Shaped like FlutterCompositor

## Context & Architecture
`AndroidExternalViewEmbedderWrapper` manages platform view composition across all supported Android composition modes:
- Hybrid Composition (HC)
- Hybrid Composition++ (HCPP)
- Virtual Display (VD)
- Texture Layer Hybrid Composition (TLHC)

It implements the engine internal `ExternalViewEmbedder` interface.
In Stage 3, platform views will transition to the Embedder API's `FlutterCompositor` abstraction (`create_backing_store_callback`, `present_view_callback`, `supports_dynamic_thread_merging`, etc.).

To prepare for Stage 3 while ensuring zero regression and 100% behavioral equivalence across all composition modes in Stage 2:
- Introduce `AndroidCompositorAdapter` as an indirection in front of `AndroidExternalViewEmbedderWrapper`.
- `AndroidCompositorAdapter` implements `ExternalViewEmbedder`, delegating all calls directly to `AndroidExternalViewEmbedderWrapper`.
- `AndroidCompositorAdapter` constructs and exposes the `FlutterCompositor` C-ABI struct shape.
- `PlatformViewAndroid::CreateExternalViewEmbedder()` constructs `AndroidExternalViewEmbedderWrapper` wrapped inside `AndroidCompositorAdapter`.
- `grep -c FlutterCompositor` in `shell/platform/android` is non-zero and properly wired.
- No files under `external_view_embedder/` are deleted (I-11).

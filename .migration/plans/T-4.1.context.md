# Context: T-4.1 — Default --android-embedder-api to On in the Tree

## Problem Statement
In Stage 3 of the Android Embedder API migration, all core platform view operations, text input, accessibility/semantics, texture registration, engine initialization/run/spawn, and all six composition modes (VD, TLHC, HC, HCPP, SurfaceTexture, SurfaceProducer) were migrated behind the `--android-embedder-api` feature flag.
With T-3.T6 completed, all Stage 3 tasks have landed and verified cleanly. Every composition mode in §B.1 of `MIGRATION_LEDGER.md` is in `embedder-behind-flag` status.
Stage 4 (Flip & Emancipation) begins with task T-4.1: flipping the default value of the `--android-embedder-api` flag from `false` to `true` across the tree.
The legacy path remains intact and reachable via explicit opt-out `--no-android-embedder-api` or `--android-embedder-api=false`.

## Scope of Changes
1. `engine/src/flutter/common/settings.h`:
   - Change `bool android_embedder_api = false;` to `bool android_embedder_api = true;`.
2. `engine/src/flutter/shell/common/switches.cc`:
   - Change default assignment when the switch is absent to `settings.android_embedder_api = true;`.
3. `engine/src/flutter/shell/common/switches_unittests.cc`:
   - Update `TEST(SwitchesTest, AndroidEmbedderApiFlag)` to assert that the default is `true`, while explicit `--android-embedder-api=false` and `--no-android-embedder-api` correctly evaluate to `false`.
4. `engine/src/flutter/shell/platform/android/platform_view_android_unittests.cc`:
   - Update `TEST_F(PlatformViewAndroidTest, AndroidEmbedderApiFlagState)` to assert that `CreateShellHolder()` defaults to `IsAndroidEmbedderApiEnabled() == true`, and explicitly setting `settings.android_embedder_api = false` results in `IsAndroidEmbedderApiEnabled() == false`.
5. `docs/platforms/android/embedder-api-migration/MIGRATION_LEDGER.md`:
   - Mark Stage 3 exit gate checklist complete.
   - Advance all six rows in §B.1 to `embedder-default` with last verified task `T-4.1`.

## Non-goals
- Deleting the legacy path or removing the flag (scheduled for T-4.5).
- Renaming `AndroidShellHolder` to `AndroidEngine` (scheduled for T-4.6).

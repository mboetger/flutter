# T-0.5 Plan: Vestigial Rendering Configuration Analysis

## Goal
Perform a written technical analysis of the candidate vestigial rendering configurations (`kSoftware`, `kSkiaOpenGLES`, `kImpellerAutoselect`, `kMergeAfterLaunch`) per `MIGRATION_LEDGER.md` §T-0.5. Determine reachability, usage, and breakage consequences. Record findings in `engine/src/flutter/docs/android/embedder_test_gaps.md` and Decision Record `DR-0017`.

## Files Touched
- `engine/src/flutter/docs/android/embedder_test_gaps.md` (append §6 Candidate Vestigial Rendering Configuration Analysis)
- `.migration/decisions/DR-0017.md` (new decision record documenting retention of configs pending upstream API level retirement)

## Implementation Sequence
1. Document technical analysis for each candidate:
   - `kSoftware`: Reachable via `--enable-software-rendering` and testing harnesses (`FlutterActivityTestRule`). Cannot be deleted without breaking testing environments.
   - `kSkiaOpenGLES`: Reachable on Android API levels 21–28 (Flutter supports `minSdkVersion` 21) and Vivante chipsets. Cannot be deleted until Android minimum API level is raised to 29 or formal deprecation concludes.
   - `kImpellerAutoselect`: Primary production path on modern Android (API >= 29). Must survive (Blocker B-1).
   - `kMergeAfterLaunch`: Maintained via `--merged-platform-ui-thread` for internal clients per plan §4. Must not be deleted.
2. Record Decision Record `DR-0017` stating that zero configurations are deleted on this branch to protect existing API 21–28 support and test rules, with removal deferred to upstream deprecation milestones.
3. Update `embedder_test_gaps.md` with §6 detailing these findings.
4. Verify formatting via `./ci/format.sh` and verification tooling.

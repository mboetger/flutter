# Context: T-3.4 — Replace `platform_view_->SetSemanticsEnabled(enabled)` with `FlutterEngineUpdateSemanticsEnabled` behind Flag

## Problem Statement
In the legacy Android embedding, enabling/disabling semantics is delivered via JNI (`nativeSetSemanticsEnabled`) to `PlatformViewAndroid::SetSemanticsEnabled(bool enabled)` which invokes `platform_view_->SetSemanticsEnabled(enabled)`.
In the standard Flutter Embedder API, semantics updates are delivered via `FlutterEngineUpdateSemanticsEnabled(engine, enabled)`.

## Scope of Changes
1. `engine/src/flutter/shell/platform/android/platform_view_android.h`:
   - Declare `FlutterEngineResult UpdateSemanticsEnabled(bool enabled);`
2. `engine/src/flutter/shell/platform/android/platform_view_android.cc`:
   - Update `SetSemanticsEnabled(bool enabled)` to branch on `android_embedder_api_`.
   - On flag-on path: emit `TRACE_EVENT1("flutter", "PlatformViewAndroid::SetSemanticsEnabled", "path", "embedder_api")` and call `UpdateSemanticsEnabled(enabled)`.
   - On legacy path: emit `TRACE_EVENT1("flutter", "PlatformViewAndroid::SetSemanticsEnabled", "path", "legacy")` and call `platform_view_->SetSemanticsEnabled(enabled)`.
   - Implement `UpdateSemanticsEnabled(bool enabled)`.
3. `engine/src/flutter/shell/platform/android/platform_view_android_unittests.cc`:
   - Update `FakePlatformViewDelegate` to capture `set_semantics_enabled_called` and `last_semantics_enabled`.
   - Add unit tests verifying legacy dispatch, embedder dispatch, and direct invocation.

## Non-goals
- Changing accessibility feature flags handling (scheduled for T-3.5).
- Modifying Java-side `AccessibilityChannel` in this task.

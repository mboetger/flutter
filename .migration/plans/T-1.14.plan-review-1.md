## 2. Documented Falsification Attempts

### Falsification Attempt 1: Map Node Pointer Stability
- **Hypothesis:** Pointers returned by `GetCallbackInformationPtr` could be invalidated if subsequent callbacks are added to the cache.
- **Investigation:** `DartCallbackCache::cache_` is a `std::map<int64_t, DartCallbackRepresentation>`. Standard associative tree containers guarantee node pointer and reference stability across insertions; inserting new elements never invalidates pointers or references to existing elements. Furthermore, `DartCallbackCache` never deletes entries.
- **Result:** Falsified. Pointers to `name`, `class_name`, and `library_path` in existing map nodes remain stable throughout process execution.

### Falsification Attempt 2: Thread-Safety Under Concurrent Lookups and Insertions
- **Hypothesis:** A lookup in `DartCallbackCache` on one thread could race with another thread adding a callback via `GetCallbackHandle`.
- **Investigation:** Both `GetCallbackHandle` and `GetCallbackInformationPtr` acquire `std::scoped_lock lock(mutex_)`. Tree traversal and node discovery are strictly synchronized. Because existing nodes and their `std::string` fields are never mutated after insertion, concurrent reads of discovered strings are data-race free.
- **Result:** Falsified. Concurrency is fully protected.

### Falsification Attempt 3: Proc Table Backward Compatibility for Legacy Callers
- **Hypothesis:** Legacy embedders calling `FlutterEngineGetProcAddresses` with older, smaller `FlutterEngineProcTable` structs could suffer buffer overflows when `GetCallbackInformation` is assigned.
- **Investigation:** In `embedder.cc`, `SET_PROC(name, func)` is defined as:
  `if (STRUCT_HAS_MEMBER(table, name)) { table->name = func; }`
  where `STRUCT_HAS_MEMBER` checks `offsetof(...) + sizeof(...) <= table->struct_size`. Legacy embedders with smaller proc table structs will safely skip the assignment.
- **Result:** Falsified. Backward compatibility is strictly guaranteed.

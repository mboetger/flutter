## 2. Documented Falsification Attempts

### Falsification Attempt 1: Raster Task Runner Deadlock
- **Hypothesis:** If `FlutterJNI.getBitmap()` is invoked or if threads are statically merged, waiting on `fml::AutoResetWaitableEvent latch` could cause a deadlock between the platform and raster threads.
- **Investigation:** `FlutterJNI.getBitmap()` is guaranteed to run on the platform thread via `ensureRunningOnPlatformThread()`. In `PlatformViewAndroid::Screenshot()`, the task is posted using `fml::TaskRunner::RunNowOrPostTask(task_runners_.GetRasterTaskRunner(), ...)`. If the calling thread is already the raster thread (such as in merged-thread mode), `RunNowOrPostTask` executes the task immediately and synchronously signals the latch before `latch.Wait()` is called. No mutual exclusion locks are acquired across the wait.
- **Result:** Falsified. Dispatch is thread-safe and deadlock-free.

### Falsification Attempt 2: Pixel Format and Vertical Inversion Mismatch with Android Bitmap
- **Hypothesis:** OpenGL `glReadPixels` reads rows starting from the bottom-left, whereas Android `Bitmap` expects rows starting from the top-left in RGBA_8888 byte order. Direct readback without inversion would produce vertically flipped bitmaps.
- **Investigation:** In `AndroidSurfaceGLSkia` and `AndroidSurfaceGLImpeller`, pixels are read into a temporary buffer and copied row-by-row inverted (`pixels + y * row_bytes` receives `temp + (height - 1 - y) * row_bytes`). Android `Bitmap.copyPixelsFromBuffer` expects packed row-by-row top-to-bottom pixels. In `AndroidSurfaceSoftware`, `SkSurface::readPixels` writes top-down with `kRGBA_8888_SkColorType`.
- **Result:** Falsified. Coordinate orientation is correctly handled.

### Falsification Attempt 3: Ratchet Violation by Introducing Internal Headers to `AndroidSurface`
- **Hypothesis:** Exposing screenshot data structures in `android_surface.h` could introduce `#include "flutter/shell/common/rasterizer.h"` or other internal engine headers, tripping `android_embedder_deps.py --check`.
- **Investigation:** `AndroidSurface` defines its own self-contained `Screenshot` struct using `sk_sp<SkData>` and `DlISize`, avoiding any include of `rasterizer.h`. The dependency ratchet script only tracks internal includes starting with `flutter/` that are outside allowed prefixes. Skia headers are already allowed third-party dependencies across the surface package. Total internal includes remain constant at 4 for `//shell/platform/android/surface:surface`.
- **Result:** Falsified. Dependency boundaries and ratchet checks remain completely unviolated.

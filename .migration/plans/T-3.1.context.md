# Context: T-3.1 — Replace `DispatchPointerDataPacket` with `FlutterEngineSendPointerEvent` behind Flag

## Context & Architecture
In the Android embedder, user input events from `AndroidTouchProcessor` arrive across JNI via `FlutterJNI.nativeDispatchPointerDataPacket(buffer, position)`.
`platform_view_android_jni_impl.cc` deserializes this byte buffer into a `flutter::PointerDataPacket` and forwards it to `PlatformViewAndroid::DispatchPointerDataPacket(packet)`.

In the legacy architecture (Stage 0–2):
`PlatformViewAndroid::DispatchPointerDataPacket` forwards directly to `platform_view_->DispatchPointerDataPacket(packet)`.

In the Embedder API architecture (Stage 3):
Pointer events are submitted using `FlutterEngineSendPointerEvent(FlutterEngine, const FlutterPointerEvent*, size_t)`.
Under T-1.6, `FlutterPointerEvent` was extended with full parity for touch geometric fields (`tilt`, `orientation`, `radius_major`, `radius_minor`, `radius_min`, `radius_max`, `distance`, `distance_max`, `size`, `embedder_id`).

In T-3.1:
- When `--android-embedder-api` is enabled, `PlatformViewAndroid::DispatchPointerDataPacket` routes through the `FlutterEngineSendPointerEvent` shape (`SendPointerEvents`).
- When `--android-embedder-api` is disabled, the legacy `platform_view_->DispatchPointerDataPacket` path is preserved unmodified.
- Both paths are traced with `TRACE_EVENT1`.
- On the flag-on path, `platform_view_` is not invoked (no dual-routing).

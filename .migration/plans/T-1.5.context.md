# T-1.5 Context: Semantics Node Field Gaps

## 1. Problem Statement
The Embedder API (`embedder.h`) defines `FlutterSemanticsNode2`, which is used by embedders via `FlutterUpdateSemanticsCallback2` to receive accessibility tree node updates.
Currently, `FlutterSemanticsNode2` lacks 10 semantic fields that exist on `flutter::SemanticsNode` (in `engine/src/flutter/lib/ui/semantics/semantics_node.h`) and are required by native accessibility services (such as Android's `AccessibilityBridge.java` and web/desktop bridges):
1. `maxValueLength`: limit on number of characters in editable text field (-1 if no limit)
2. `currentValueLength`: current character count in editable text field (-1 if no limit)
3. `traversalParent`: node ID of parent for accessibility traversal order
4. `minValue`: minimum value if node represents a range
5. `maxValue`: maximum value if node represents a range
6. `hitTestTransform`: 4x4 transform matrix used during hit testing
7. `linkUrl`: URI that this node links to
8. `role`: accessibility role of the node (`SemanticsRole`)
9. `validationResult`: form field validation result (`SemanticsValidationResult`)
10. `locale`: BCP 47 locale string of the content in this node

Without these fields in `FlutterSemanticsNode2`, embedders cannot express editable text field length restrictions, traversal parents, range bounds, hit test transformations, link URLs, semantic roles (e.g. tab, dialog, progress bar), validation state, or node locale. In earlier migration attempts, workarounds like hardcoding `maxValueLength = 0` and `traversalParent = -1` caused silent regressions in TalkBack announcements and focus order.

## 2. Constraints & Invariants
- **C-ABI Backward Compatibility (§6.1 Rule 1 & Rule 2):**
  - All new fields must be strictly appended to `FlutterSemanticsNode2`.
  - Field access by embedders must use `SAFE_ACCESS(node, member, fallback)` based on `node->struct_size`.
  - Existing struct members cannot be moved, resized, or reordered.
  - `FLUTTER_ENGINE_VERSION` must NOT be bumped (§G.5, §G.9 Item 2). Forward compatibility is managed exclusively via `struct_size` and `SAFE_ACCESS`.
- **Layering & Scope (§A.1 I-9, I-10):**
  - All modifications are strictly within the embedder API layer: `shell/platform/embedder/`.
  - No Android code or Android platform files (`shell/platform/android/`) may be touched in Stage 1. Android consumers will adopt these fields in Stage 3.
  - No Android-specific naming or assumptions in shared embedder code.
- **String Lifetimes:**
  - `min_value`, `max_value`, `link_url`, and `locale` are guaranteed to remain valid for the duration of the `FlutterUpdateSemanticsCallback2` invocation.
- **Testing & Verification:**
  - Automated host unit tests in `embedder_a11y_unittests.cc` asserting that every appended field is faithfully translated and round-tripped with non-default values.

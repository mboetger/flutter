## 1. Plan Verification & Scope Assessment
The implementation plan for T-1.16 satisfies all requirements established in `MIGRATION_LEDGER.md` §T-1.16:
- Introduces `FlutterGetScaledFontSizeCallback` in `embedder.h` and appends `get_scaled_font_size_callback` to `FlutterProjectArgs`.
- Maintains `FLUTTER_ENGINE_VERSION = 1` invariant, relying on `struct_size` and `SAFE_ACCESS`.
- Implements `PlatformViewEmbedder::GetScaledFontSize`, safely delegating to the embedder callback when present and returning `unscaled_font_size` (1:1 scaling) when null, eliminating the `FML_UNREACHABLE()` crash.
- Wires the callback through `embedder.cc`.
- Adds unit tests in `platform_view_embedder_unittests.cc` and integration tests in `embedder_unittests.cc` verifying both callback execution and safe fallback.

## 2. Documented Falsification Attempts

### Falsification Attempt 1: Struct ABI Compatibility and Field Sizing in `FlutterProjectArgs`
- **Hypothesis:** Appending `get_scaled_font_size_callback` to `FlutterProjectArgs` without bumping `FLUTTER_ENGINE_VERSION` will cause buffer out-of-bounds reads or crashes for legacy embedders compiled against earlier header revisions.
- **Investigation:** `FlutterProjectArgs.struct_size` is explicitly initialized by the caller. All field accesses in `embedder.cc` utilize the `SAFE_ACCESS(args, get_scaled_font_size_callback, nullptr)` macro, which evaluates the offset against `args->struct_size`. If an older embedder passes a struct size predating this field, `SAFE_ACCESS` safely yields `nullptr`. Bumping `FLUTTER_ENGINE_VERSION` is explicitly prohibited by migration rules (§G.5/G.9).
- **Result:** Falsified. ABI backward and forward compatibility is completely preserved.

### Falsification Attempt 2: Crash or Invalid State on Unimplemented Embedder Queries
- **Hypothesis:** When an embedder omits `get_scaled_font_size_callback`, returning `unscaled_font_size` from `PlatformViewEmbedder::GetScaledFontSize` could trigger assertions or invalid state in `dart:ui`.
- **Investigation:** In `lib/ui/platform_dispatcher.dart`, `scaleFontSize` validates `fontSize >= 0`. If `_getScaledFontSize` returns a positive number (such as `unscaled_font_size`), Dart caches this value as the scaled font size. Returning `unscaled_font_size` produces a linear 1:1 scale, which is the expected default for embedders that do not implement dynamic accessibility font curves. In contrast, the inherited base `PlatformView::GetScaledFontSize` executes `FML_UNREACHABLE()` which immediately aborts the process.
- **Result:** Falsified. Returning `unscaled_font_size` is valid, non-destructive, and prevents fatal engine aborts.

### Falsification Attempt 3: Thread Safety of Synchronous Invocation from Dart UI Thread
- **Hypothesis:** Invoking `get_scaled_font_size_callback` synchronously on the UI thread may conflict with embedders that only track metrics on the platform thread, risking data races or deadlocks.
- **Investigation:** `PlatformDispatcher._getScaledFontSize` is called synchronously during text layout on the UI thread. The C-API documentation in `embedder.h` explicitly informs embedders that this callback executes synchronously on the UI task runner. Embedders handling asynchronous platform configuration updates (like Android's `pastDisplayMetrics` cache in `FlutterJNI`) are responsible for thread-safe access. This pattern precisely mirrors existing synchronous embedder callbacks such as `gl_external_texture_frame_callback`.
- **Result:** Falsified. Synchronous invocation on the UI task runner matches Dart engine requirements and is properly documented.

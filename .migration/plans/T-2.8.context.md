# Context: T-2.8 — Restructure AndroidShellHolder toward FlutterProjectArgs Construction

## Context & Architecture
`AndroidShellHolder` is the primary C++ orchestrator for the Android embedding. It manages:
- Thread creation and configuration (`AndroidTaskRunners`, extracted in T-2.5).
- Asset resolution (`APKAssetProvider`, extracted in T-2.6).
- Platform view and embedder dispatching (`PlatformViewAndroid` and `PlatformViewEmbedder`, refactored in T-2.1-T-2.4).
- Surface lifecycle management (`AndroidSurfaceLifecycle`, extracted in T-2.7).

In Stage 3, `AndroidShellHolder` will initialize and run the engine via the Embedder API (`FlutterEngineInitialize` + `FlutterEngineRunInitialized` or `FlutterEngineRun`) using `FlutterProjectArgs` rather than calling `Shell::Create`.

To prepare for Stage 3 while preserving 100% behavioral equivalence in Stage 2:
- Restructure `AndroidShellHolder` to construct and maintain the `FlutterProjectArgs` structure from its components (`AndroidTaskRunners`, `APKAssetProvider`, `Settings`, `PlatformViewAndroidJNI`).
- Connect `custom_task_runners`, `asset_resolvers`, and JNI callback bridges in the shape required by the Embedder API.
- Keep `Shell::Create` and all existing execution paths 100% intact.

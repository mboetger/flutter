## 1. Plan Verification & Scope Assessment

## 2. Documented Falsification Attempts

### Falsification Attempt 1: Lifetime of Stack-Allocated Threading Info in Callbacks
- **Hypothesis:** Allocating `_FlutterRasterThreadMerger` and `FlutterFrameThreadingInfo` on the stack inside `PostPrerollAction`, `BeginFrame`, and `EndFrame` will lead to use-after-free if the embedder retains the merger reference or threading info pointer.
- **Investigation:** The API contract documented in `embedder.h` explicitly stipulates that `FlutterRasterThreadMergerRef` and `FlutterFrameThreadingInfo` are valid **only for the duration of the callback**. Neither the engine nor the embedder may retain pointers across returns. Stack allocation ensures zero heap allocation overhead per frame and guaranteed deterministic cleanup immediately after callback return.
- **Result:** Falsified. Stack allocation strictly enforces the documented lifetime contract without heap allocation overhead.

### Falsification Attempt 2: Null RasterThreadMerger Handling When Merging is Disabled or Statically Merged
- **Hypothesis:** When task runners are statically merged (e.g. single-threaded mode or non-dynamic merging), `raster_thread_merger` passed to `BeginFrame`, `EndFrame`, or `PostPrerollAction` may be `nullptr`, causing null-pointer dereferences in the engine.
- **Investigation:** `EmbedderExternalViewEmbedder` guards access defensively:
  `thread_merger = raster_thread_merger ? &merger_wrapper : nullptr`
  `is_on_platform_thread = raster_thread_merger ? raster_thread_merger->IsOnPlatformThread() : false`
  Additionally, all accessors in `embedder.cc` (`FlutterRasterThreadMergerIsMerged`, etc.) begin with `if (!merger || !merger->merger) return ...`.
- **Result:** Falsified. Null handles and null mergers are safely handled across all layers.

### Falsification Attempt 3: Backward Compatibility for Embedders Using Older FlutterCompositor Structs
- **Hypothesis:** If an existing embedder initializes `FlutterCompositor` with an older struct size that predates the addition of dynamic thread merging fields, reading those fields in `InferExternalViewEmbedderFromArgs` will read uninitialized or out-of-bounds memory.
- **Investigation:** `SAFE_ACCESS` is used for every newly introduced field in `InferExternalViewEmbedderFromArgs`:
  - `supports_dynamic_thread_merging` defaults to `false`.
  - `post_preroll_callback` defaults to `nullptr`.
  - `begin_frame_callback` defaults to `nullptr`.
  - `end_frame_callback` defaults to `nullptr`.
  If the struct size provided by the embedder is smaller than the offset of these fields, `SAFE_ACCESS` returns the safe default (`false` / `nullptr`) without reading past the caller's allocated struct.
- **Result:** Falsified. `SAFE_ACCESS` ensures complete backward compatibility for older embedder struct sizes.

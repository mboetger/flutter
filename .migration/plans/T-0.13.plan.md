# T-0.13 Plan: Thread Merging API Extension (Blocker B-4)

## Goal
Design the C-ABI extension for the Embedder API to expose dynamic raster thread merging capabilities, enabling Hybrid Composition (HC) platform views to synchronize raster and platform threads on Android while remaining entirely inert and optional for desktop/iOS/macOS embedders.

## Files Touched
- `engine/src/flutter/docs/android/embedder_migration_b4_thread_merging.md` (new)
- `.migration/HUMAN_REVIEW_REQUIRED.md` (append sign-off requirement)

## Implementation Sequence
1. Document the failure mechanics of unmerged HC:
   - JNI threading rules requiring platform thread execution for `FlutterViewBeginFrame` / `FlutterViewEndFrame`.
   - UI thread deadlocks and tearing when platform views render asynchronously from raster threads.
2. Characterize lease behavior and hysteresis:
   - Prove continuous 10-frame lease renewal during active scrolling (`ExtendLeaseTo(10)` on every frame).
   - Document lease decay and clean unmerge on 10th frame after platform views leave viewport.
3. Validate the C-ABI design choices:
   - Exposing explicit lease controls (`MergeWithLease`, `ExtendLeaseTo`) vs engine-managed lease.
   - Opaque handle lifetime: `FlutterRasterThreadMergerRef` is scoped strictly to callback execution duration.
   - Guarding begin/end frame callbacks with `is_on_platform_thread` flag in `FlutterFrameThreadingInfo`.
   - Hard error during `FlutterEngineInitialize` if `supports_dynamic_thread_merging` is true without `post_preroll_callback` (I-1).
4. Analyze interaction with `--merged-platform-ui-thread` (`kMergeAfterLaunch`):
   - Static queue equality in `RasterThreadMerger` makes all dynamic lease operations no-ops; safe coexistence.
5. Provide the exact, complete C-ABI specification to be implemented in T-1.18.
6. Specify host-side non-Android unit test for T-1.18 (`EmbedderTest.CompositorDynamicThreadMerging`).
7. Append human review entry to `.migration/HUMAN_REVIEW_REQUIRED.md`.

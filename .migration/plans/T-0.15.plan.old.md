# Plan for T-0.15

## Goal
To build `dev/tools/bin/migration_verify.dart`, a verification tool for the migration pipeline enforcing gate execution correctness and branch SHA persistence. Observable behaviour change: None (tooling only).

## Split Implementation Sequence

The tool requires gates management, JSON schemas, stack walking, pipeline checking, markdown generation, device locking, and multiple anti-fabrication steps. This exceeds the 400-line invariant I-7 budget limit if implemented at once. We split the execution into:

### T-0.15a: Tooling core, artifact generation, and pipeline completion checks

| Field | Value |
|---|---|
| **Task ID and title** | T-0.15a — Verification tooling core and artifacts |
| **Goal, one sentence** | Create the core verification JSON schema, `--task`/`--gates` executors, and `--check-artifact-sha` pipeline completeness validator. |
| **Depends on** | T-0.0 |
| **Flag** | none |
| **Behaviour change: yes/no** | No |
| **Anchor** | `dev/tools/bin/migration_verify.dart` |
| **Composition impact** | none — tooling only |

**Steps:**
1. Create `dev/tools/bin/migration_verify.dart` and `.migration/README.md`.
2. Implement `--task` and `--gates` arguments wrapping `Isolate.run()` to fork gates externally via `Process.run`.
3. Implement JSON schema creation and emit the human-readable markdown block (Requirement 6).
4. Implement "dirty tree" checking (`git status`).
5. Assert `--update-goldens` cannot be passed (Requirement 8).
6. Implement `--check-artifact-sha` to assert the generated `commit_sha` equals the current branch `HEAD` AND explicitly fail if `.migration/plans/<id>.plan.md`, at least one approved `plan-review-*.md`, and at least one approved `code-review-*.md` are missing from the branch (Requirement 9).
7. **Requirement 1:** Always record `commit_sha` and `parent_sha` strictly from `git rev-parse`. Never accept them as CLI arguments.
8. **Requirement 3:** Guarantee that `"ran": false` with a reason string is encoded as a valid parsed outcome.
9. **Requirement 4:** Exit non-zero if any gate failed during execution.

### T-0.15b: Stack Audit and Device Lock Management

| Field | Value |
|---|---|
| **Task ID and title** | T-0.15b — Stack audit and device lock |
| **Goal, one sentence** | Implement across-branch history checking (`--audit-stack`) and exclusive hardware lock (`--device-lock`). |
| **Depends on** | T-0.15a |
| **Flag** | none |
| **Behaviour change: yes/no** | No |
| **Anchor** | `dev/tools/bin/migration_verify.dart` |
| **Composition impact** | none — tooling only |

**Steps:**
1. Add `--audit-stack` that iterates backwards through `git log` checking `parent_sha` and `commit_sha` for all JSON artifacts.
2. Implement `--device-lock` to ensure `/tmp/android-embedder-v8.device.lock` is acquired and released natively (via Dart file locking).
3. Inside the lock context, programmatically capture `adb get-serialno` and evaluate all §A.7 preconditions structurally.
4. Execute the wrapped `<cmd>` passed via CLI.
5. Provide a hard cleanup (`adb uninstall` targeted app and `adb logcat -c`) before releasing the lock.
6. Wire `--summary` to read all historical artifacts and fully regenerate the §B dashboard, the §B.1 tracker, and the §E.3 decision index.

Tests failing before (absent tool) and passing after (preventing circumvention) within `dev/tools/test/migration_verify_test.dart`:

- `test('ran: false with a reason survives serialization round-trip')`: Validate serialization accurately preserves `"ran": false` blocks and does not interpret them as successful (T-0.15a).
- `test('rejects execution if --update-goldens is passed')`: Simulate args with `--update-goldens` expecting an exit code of 1 and immediate termination (T-0.15a).

- `test('--audit-stack reports mismatch when commit_sha does not equal branch HEAD')`: Artificially mutate an artifact's `commit_sha` preventing execution (T-0.15b).
- `test('--device-lock blocks concurrent acquisitions')`: Programmatically spawn two isolates attempting `--device-lock`, verifying the second blocks until the first completes (T-0.15b).

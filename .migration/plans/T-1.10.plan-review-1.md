# Plan Review: T-1.10 — OpenGL: UV Transform Matrix & Platform Views on GLES

- **Reviewer:** Plan Reviewer (Embedder API & Android Graphics Architecture)
- **Date:** 2026-09-16
- **Verdict:** **APPROVE**

## 1. Scope and Ledger Alignment
- The plan directly addresses the gap inventory from Blocker B-5 (`engine/src/flutter/docs/android/embedder_external_texture_gaps.md`) and task T-1.10 in `docs/platforms/android/embedder-api-migration/MIGRATION_LEDGER.md`:
  - Adds 4x4 UV transformation matrix to `FlutterOpenGLTexture` to bridge Android `SurfaceTexture.getTransformMatrix(float[16])`.
  - Implements UV transformation painting via DisplayList image shader (`DlColorSource::MakeImage`) with inversion and orientation correction.
  - Closes the Impeller GLES gap where `GL_TEXTURE_EXTERNAL_OES` was improperly treated as `kTexture2D`.
  - Implements `MakeRenderTargetFromBackingStoreImpeller` for `kFlutterOpenGLTargetTypeTexture`, enabling Impeller GLES compositors to render into texture backing stores during platform view compositing.

## 2. C-ABI Invariants & Safety (§6.1)
- `double transformation[16]` is strictly appended to `FlutterOpenGLTexture`.
- Struct zero-initialization via `std::make_unique<FlutterOpenGLTexture>()` ensures legacy callers leaving the new fields unpopulated evaluate to all-zero, cleanly recognized as unpopulated/identity.
- `FLUTTER_ENGINE_VERSION` is not bumped, preserving established convention (§G.5, §G.9 Item 2).
- Zero Android types, zero NDK headers, and zero `#if defined(__ANDROID__)` in `shell/platform/embedder/`. Standard C types and OpenGL tokens only.

## 3. Rendering & Mathematical Correctness
- `DlColorSource::MakeImage` takes the inverse of the coordinate lookup matrix to transform image sampling coordinates, exactly matching the proven Android implementation in `SurfaceTextureExternalTexture::DrawFrame`.
- When `transformation` is all-zero or identity, execution takes the fast path (`canvas->DrawImage` / `canvas->DrawImageRect`), avoiding any shader or state allocation overhead.
- Non-invertible matrices are trapped and logged without crashing or undefined behavior.

## 4. Test Strategy
- Host unit tests in `embedder_gl_unittests.cc` will execute in CI/host environments without hardware device dependencies.
- Covers transformation matrix propagation, `GL_TEXTURE_EXTERNAL_OES` target handling under Impeller GLES, texture backing store creation, and platform view rendering on GLES.

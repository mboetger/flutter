# Context: T-3.5 — Replace `platform_view_->SetAccessibilityFeatures(flags)` with `FlutterEngineUpdateAccessibilityFeatures` behind Flag

## Problem Statement
In the legacy Android embedding, accessibility features are delivered via JNI (`nativeSetAccessibilityFeatures`) to `PlatformViewAndroid::SetAccessibilityFeatures(int32_t flags)` which invokes `platform_view_->SetAccessibilityFeatures(flags)`.
In the standard Flutter Embedder API, accessibility feature updates are delivered via `FlutterEngineUpdateAccessibilityFeatures(engine, features)`.

## Scope of Changes
1. `engine/src/flutter/shell/platform/android/platform_view_android.h`:
   - Declare `FlutterEngineResult UpdateAccessibilityFeatures(FlutterAccessibilityFeature features);`
2. `engine/src/flutter/shell/platform/android/platform_view_android.cc`:
   - Update `SetAccessibilityFeatures(int32_t flags)` to branch on `android_embedder_api_`.
   - On flag-on path: emit `TRACE_EVENT1("flutter", "PlatformViewAndroid::SetAccessibilityFeatures", "path", "embedder_api")` and call `UpdateAccessibilityFeatures(static_cast<FlutterAccessibilityFeature>(flags))`.
   - On legacy path: emit `TRACE_EVENT1("flutter", "PlatformViewAndroid::SetAccessibilityFeatures", "path", "legacy")` and call `platform_view_->SetAccessibilityFeatures(flags)`.
   - Implement `UpdateAccessibilityFeatures(FlutterAccessibilityFeature features)`.
3. `engine/src/flutter/shell/platform/android/platform_view_android_unittests.cc`:
   - Update `FakePlatformViewDelegate` to capture `set_accessibility_features_called` and `last_accessibility_features`.
   - Add unit tests verifying legacy dispatch, embedder dispatch, and direct invocation.

## Non-goals
- Modifying Java-side `AccessibilityChannel` or `FlutterJNI` in this task.
- External texture migration (scheduled for T-3.6).

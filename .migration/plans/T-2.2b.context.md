## Background & Objectives
Following T-2.1 (which established the `platform_view_` delegate pointer and verified `NotifyDestroyed`) and T-2.2a (which migrated semantics, locale, and font scaling overrides), T-2.2b continues migrating the remaining overrides of `PlatformView` across the delegate seam.

Per `MIGRATION_LEDGER.md` §Stage 2 and §A.2, migrations are batched in ~3–5 methods per task to ensure small diffs, strict reviews, and high verification fidelity.

T-2.2b addresses the second batch of 6 overrides:
1. `HandlePlatformMessage(std::unique_ptr<flutter::PlatformMessage> message)`
2. `OnPreEngineRestart() const`
3. `RequestDartDeferredLibrary(intptr_t loading_unit_id)`
4. `LoadDartDeferredLibrary(intptr_t loading_unit_id, std::unique_ptr<const fml::Mapping> snapshot_data, std::unique_ptr<const fml::Mapping> snapshot_instructions)`
5. `LoadDartDeferredLibraryError(intptr_t loading_unit_id, const std::string error_message, bool transient)`
6. `UpdateAssetResolverByType(std::unique_ptr<AssetResolver> updated_asset_resolver, AssetResolver::AssetResolverType type)`

When `platform_view_` is set, each method delegates to `platform_view_->Method(...)`.
When `platform_view_` is null, each method maintains its existing behavior.
Unit tests in `platform_view_android_unittests.cc` exercise both paths, and Stage 0 characterization tests pass unmodified.

# T-0.3 Context Pack: Threading, Priority, and Merging Characterization

## 1. Ground Truth Verification
- `shell/platform/android/android_shell_holder.cc`:
  - `AndroidPlatformThreadConfigSetter`:
    - `kBackground`: `setpriority(PRIO_PROCESS, 0, 10)`
    - `kDisplay`: `setpriority(PRIO_PROCESS, 0, -1)`
    - `kRaster`: `setpriority(PRIO_PROCESS, 0, -5)` (fallback `-2`)
    - default / `kNormal`: `setpriority(PRIO_PROCESS, 0, 0)`
    - Worker threads: `setpriority(PRIO_PROCESS, gettid(), 1)`
  - IO thread configuration in `AndroidShellHolder`:
    - Configured as `fml::Thread::ThreadPriority::kNormal` (priority 0), in contrast to engine-managed default `kBackground` (priority 10).
  - Dynamic thread merging:
    - `AndroidExternalViewEmbedder::SupportsDynamicThreadMerging()` returns `true`.
    - `AndroidExternalViewEmbedder2::SupportsDynamicThreadMerging()` returns `false`.
    - `AndroidExternalViewEmbedderWrapper::SupportsDynamicThreadMerging()` forwards to `hcpp_view_embedder_` (false) or `non_hcpp_view_embedder_` (true).
  - `kMergeAfterLaunch`:
    - Merges UI queue into platform queue in `Engine::Run()` via `fml::MessageLoopTaskQueues::Merge()`.

## 2. Current Code & Thread Affinities
- Vsync callback: Dispatched to UI task runner via `OnVsyncFromNDK` / `ConsumePendingCallback`.
- Platform message dispatch: Delivers to Java on platform thread via `FlutterViewHandlePlatformMessage`.
- External texture registration: Platform thread.
- Semantics update: Platform thread.

## 4. What v7 Did
- v7 adopted engine-managed threads without characterizing priorities, silently dropping Android's IO thread priority from `kNormal` (0) to `kBackground` (10).
- v7 broke Hybrid Composition by ignoring `SupportsDynamicThreadMerging`.

## 5. Parity Contract Constants
- UI Thread Priority: `-1`
- Raster Thread Priority: `-5` (or `-2`)
- IO Thread Priority: `0` (`kNormal` on Android)
- Platform Thread Priority: `0`
- Worker Thread Priority: `1`

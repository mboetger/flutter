# T-1.10 Context: OpenGL UV Transform Matrix & Platform Views on GLES

## 1. Problem Statement
In Flutter on Android, external textures and platform view composition on OpenGL ES (GLES) are vital for:
1. **Virtual Display (VD) Platform Views:** Rendered through `SurfaceTextureExternalTexture` and sampled as an external texture.
2. **Camera and Video Plugins:** Stream frames into `SurfaceTexture` / `SurfaceProducer`, producing a 4x4 affine/perspective UV coordinate transformation matrix (`SurfaceTexture.getTransformMatrix(float[16])`) to correct for sensor rotation, vertical axis inversion, and cropping.
3. **Platform View Compositing on GLES:** When an embedder uses custom compositor backing stores on GLES, it allocates OpenGL texture or framebuffer render targets for composited layers.

As identified in Blocker B-5 (`engine/src/flutter/docs/android/embedder_external_texture_gaps.md`) and architectural comments by Chris and Loïc (*"no uv transform matrix iirc"*, *"no in-tree embedder that uses the embedder API's OpenGL implementation also implements platform views, so I wouldn't be surprised if there are gaps there as well"*):
1. **Missing UV Transformation in `FlutterOpenGLTexture`:** `FlutterOpenGLTexture` contains target, name, format, user_data, destruction_callback, width, and height, but no transformation matrix.
2. **Missing UV Transformation Handling in `EmbedderExternalTextureGL`:** `EmbedderExternalTextureGL::Paint` only performs un-transformed `DrawImage` or `DrawImageRect`. It does not apply any UV transformation matrix via `DlColorSource::MakeImage`.
3. **Missing `GL_TEXTURE_EXTERNAL_OES` Support in Impeller GLES:** `EmbedderExternalTextureGL::ResolveTextureImpeller` wraps textures without inspecting `texture->target`, defaulting `desc.type` to `kTexture2D`. In OpenGL ES, binding a `GL_TEXTURE_EXTERNAL_OES` texture as `GL_TEXTURE_2D` causes `GL_INVALID_OPERATION`.
4. **Missing Texture Backing-Store Support in Impeller GLES:** In `embedder.cc`, `MakeRenderTargetFromBackingStoreImpeller` is implemented only for `framebuffer` (`FlutterOpenGLFramebuffer`). When an embedder allocates `kFlutterOpenGLTargetTypeTexture` backing stores with Impeller GLES enabled, `embedder.cc` falls through to Skia's `MakeSkSurfaceFromBackingStore` where `context` is null, failing to create the render target.

## 2. Constraints & Invariants
- **C-ABI Backward Compatibility (§6.1 Rule 1 & Rule 2):**
  - Append `double transformation[16]` (or column-major 4x4 UV transformation) to `FlutterOpenGLTexture`.
  - Zero-initialization via `std::make_unique<FlutterOpenGLTexture>()` guarantees that older embedders leaving new fields unwritten default to all-zero (treated as identity).
  - Do NOT bump `FLUTTER_ENGINE_VERSION` (§G.5, §G.9 Item 2).
- **Layering & Scope (§A.1 I-9, I-10):**
  - All changes restricted strictly to `shell/platform/embedder/`.
  - No Android types, no NDK headers, and no `#if defined(__ANDROID__)` in `shell/platform/embedder/`. Standard OpenGL types and opaque handles only.
- **Rendering Correctness (§A.1 I-11):**
  - When `transformation` is non-identity, `EmbedderExternalTextureGL::Paint` applies the inverted UV transform via `DlColorSource::MakeImage` and canvas orientation adjustment (matching `SurfaceTextureExternalTexture::DrawFrame`).
  - When `target == GL_TEXTURE_EXTERNAL_OES` (0x8D65), Impeller GLES sets `desc.type = impeller::TextureType::kTextureExternalOES`.
  - `MakeRenderTargetFromBackingStoreImpeller` handles `const FlutterOpenGLTexture* texture` so embedders compositing platform views into texture backing stores succeed on Impeller GLES.
- **Testing & Verification (Rule 7 in `MIGRATION_LEDGER.md`):**
  - Host tests in `embedder_gl_unittests.cc` verifying:
    - External texture rendering with identity vs non-identity UV transformation matrix.
    - External texture resolution with `GL_TEXTURE_EXTERNAL_OES` target under Impeller GLES and Skia.
    - OpenGL texture backing-store render target creation and rendering under Impeller GLES.
    - GLES platform view mutator and composition verification.

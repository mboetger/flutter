## 1. Problem Statement & Motivation
In Flutter applications, `PluginUtilities.getCallbackHandle` in `dart:ui` produces persistent 64-bit integer handles representing top-level functions or static methods. These handles are used by background execution plugins (e.g. background messaging, work managers, alarms, geofencing) to persist entrypoint references across application restarts.

In the legacy Android implementation:
- `FlutterJNI.nativeLookupCallbackInformation(long handle)` invoked `DartCallbackCache::GetCallbackInformation(handle)` directly from `platform_view_android_jni_impl.cc`.
- `flutter_main.cc` initialized `DartCallbackCache::SetCachePath(...)` and `DartCallbackCache::LoadCacheFromDisk()`.

However, the public Embedder API (`embedder.h`) lacks a query function to resolve callback information from a 64-bit handle. Without this API:
1. An embedder isolated behind `embedder.h` cannot resolve callback handles without including private internal engine headers (`lib/ui/plugins/callback_cache.h`).
2. The Android JNI layer cannot be migrated away from internal headers to pure Embedder C-API in Stage 2/Stage 3 without breaking background callback execution.

## 2. Technical Solution
1. **Public C-ABI Struct (`FlutterCallbackInformation`):**
   ```c
   typedef struct {
     size_t struct_size;
     const char* callback_name;
     const char* class_name;
     const char* library_path;
   } FlutterCallbackInformation;
   ```
2. **Public C-API Function & Proc Table:**
   ```c
   FLUTTER_EXPORT
   FlutterEngineResult FlutterEngineGetCallbackInformation(
       int64_t handle,
       FlutterCallbackInformation* info_out);
   ```
   Add `FlutterEngineGetCallbackInformationFnPtr` and append `GetCallbackInformation` to `FlutterEngineProcTable`.
3. **Engine Implementation:**
   - Add `DartCallbackCache::GetCallbackInformationPtr(int64_t handle)` in `lib/ui/plugins/callback_cache.{h,cc}`. Because `DartCallbackCache::cache_` is a `std::map<int64_t, DartCallbackRepresentation>`, node references are stable across insertions, guaranteeing that `c_str()` pointers remain valid for the process lifetime.
   - Implement `FlutterEngineGetCallbackInformation` in `embedder.cc` validating `info_out != nullptr` and `SAFE_ACCESS(info_out, struct_size, 0) == sizeof(FlutterCallbackInformation)`.
   - Wire `GetCallbackInformation` into `FlutterEngineGetProcAddresses`.
4. **Verification & Tests:**
   - Host unit tests in `embedder_unittests.cc` validating null arguments, bad struct sizes, non-existent handles, class method lookups, top-level function lookups, and proc table resolution.
   - Proc table consistency verified by existing `EmbedderProcTable.AllPointersProvided` and `EmbedderProcTable.NoDuplicatePointers`.

## 3. Invariants & Guardrails
- **`FLUTTER_ENGINE_VERSION` Invariant:** Maintained at 1.
- **Backward/Forward Compatibility:** `FlutterEngineProcTable` appends at the end. Caller supplies `struct_size` checked via `SAFE_ACCESS`.
- **Zero Android Contamination (I-10):** No Android types, NDK headers, or preprocessor flags in `embedder.h` or `embedder.cc`.
- **Pure Host Verification:** Full unit test coverage in `embedder_unittests.cc`.

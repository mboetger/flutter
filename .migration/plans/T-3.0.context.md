# Context: T-3.0 — Introduce `--android-embedder-api` Feature Flag and Plumbing

## Context & Architecture
Per `MIGRATION_PLAN.md` §3 and `MIGRATION_LEDGER.md` §Stage 3:
- Stage 3 ("Adherence") incrementally replaces internal engine calls with their Embedder API equivalents (`FlutterEngineSendPointerEvent`, `FlutterEngineSendWindowMetricsEvent`, etc.) and migrates composition modes one at a time behind a single runtime feature flag:
  ```
  --android-embedder-api=true|false
  ```
- The flag defaults to `false` (legacy behavior).
- The flag is read once at engine initialization from the command line, cached on `Settings`, `AndroidShellHolder`, and `PlatformViewAndroid`, and never re-read mid-lifecycle.
- Every flagged branch point must be `TRACE_EVENT`-instrumented with the resolved path.
- The Android integration suite and unit tests must be runnable in both flag states.

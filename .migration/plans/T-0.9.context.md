# Context: Task T-0.9 — Dependency Ratchet Tooling

## Problem Statement
The ultimate architectural goal of the Android embedder migration is for `shell/platform/android` to depend only on:
1. `//flutter/fml`
2. `//flutter/assets`
3. `//flutter/common`
4. Embedder API (`embedder.h` / `//flutter/shell/platform/embedder:embedder_headers`)

In previous attempts (v7), dependency boundaries were enforced through a quarantined GN build target that was completely isolated from the main build, which led to a brittle parallel rewrite that ceased compiling.
Instead of an artificial quarantine, this migration establishes a continuous **dependency ratchet**:
- The real target is measured continuously.
- Any increase in internal-engine GN dependencies, internal-engine `#include` headers, or `// nogncheck` occurrences causes a hard build/CI failure.
- As adherence tasks remove internal dependencies throughout the migration, the ratchet baseline is lowered, permanently locking in progress and preventing relapse.

## Governing Invariants & Principles
- **I-8 (No nogncheck without bug):** nogncheck comments are tracked and counted.
- **I-10 (No Android in shared embedder code / no engine internals in embedder):** Dependency count must only decrease or stay level.
- **§A.3 / §A.6:** Tooling must be automated, reproducible, and verifiable locally and in CI.
- Pre-wired in `dev/tools/lib/migration_verify.dart`: `'ratchet': ['python3', 'engine/src/flutter/tools/android_embedder_deps.py', '--check']`.

## Scope & Deliverables
1. `engine/src/flutter/tools/android_embedder_deps.py`:
   - Scans all BUILD.gn files in `shell/platform/android/` and its subdirectories (`context`, `external_view_embedder`, `jni`, `platform_view_android_delegate`, `surface`).
   - Counts internal-engine GN dependencies (anything starting with `//flutter/` outside the allowed list and outside `shell/platform/android`).
   - Counts internal-engine `#include`s in all target source files.
   - Counts `// nogncheck` occurrences across GN and source files.
   - Provides `--check`, `--update-baseline`, and human-readable summary/table output.
2. `engine/src/flutter/tools/android_embedder_deps_baseline.json`:
   - Machine-readable baseline recording targets and their counts.
3. Verification with `--check` passing on the current baseline and demonstrating failure on injected violation.

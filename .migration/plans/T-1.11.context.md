# T-1.11 Context: FlutterEngineSpawn in Embedder C-API

## 1. Problem Statement
In Flutter on Android, multi-engine architectures (`FlutterEngineGroup`, Add-to-App, multiple activities/fragments, background tasks, and split-screen experiences) rely heavily on spawning lightweight secondary engines from an existing engine. Spawning engines from a common parent confers critical advantages:
1. **Shared Dart VM and Isolate Groups:** Secondary isolates are spawned into existing isolate groups or VM instances, dramatically lowering heap footprint and memory overhead (~180KB per spawned engine instead of ~30MB).
2. **Shared Graphics/Platform Context (`AndroidContext` / `IOSContext`):** Reusing the parent engine's graphics context (`AndroidContextVKImpeller`, `AndroidContextGLImpeller`, or `IOSContext`) avoids re-probing Vulkan/GLES capabilities and recreating driver instances, eliminating 20-50ms startup latency.
3. **Shared Thread Host & Task Runners:** Spawning shells share the platform, UI, raster, and IO task runners without spawning duplicate threads or exhausting thread quotas.

Currently, `shell_->Spawn(...)` exists in `Shell` (`engine/src/flutter/shell/common/shell.h`) and is utilized internally by `AndroidShellHolder::Spawn` and `FlutterEngine.mm` (iOS). However, the public Embedder API (`embedder.h`) has no entry point to spawn an engine. Embedders attempting to create multiple engines must call `FlutterEngineInitialize` repeatedly, creating disjoint VMs and separate thread hosts.

As identified in the Android Embedder API Migration Ledger (§G.10 c10/c11):
- Loïc & Chris Bracken: *"FlutterEngineSpawn needs `initial_route`; **use the info-struct pattern** — Chris: '+1 absolutely agreed'"*.
- Architectural requirements from `v7-post-mortem.md` (§6.1 Rule 2):
  - v7 introduced a critical bug in `FlutterEngineSpawn` by hard-checking `config->struct_size < sizeof(FlutterEngineSpawnConfig)`. This defeated forward compatibility: when any field is appended in a future release, older embedders are rejected.
  - Forward/backward compatibility must be strictly maintained via `SAFE_ACCESS` on all struct fields, and `never struct_size < sizeof(...)`.
  - `FLUTTER_ENGINE_VERSION` has remained at `1` since inception and must never be bumped (§G.5, §G.9).
  - The proc table (`FlutterEngineProcTable`) must be extended by appending `FlutterEngineSpawnFnPtr Spawn` at the end, verified by `embedder_unittests_proctable.cc`.

## 2. Constraints & Invariants
- **C-ABI Backward & Forward Compatibility (§6.1 Rule 1, 2, 3):**
  - Define `FlutterEngineSpawnConfig` using the info-struct pattern with `size_t struct_size`.
  - Use `SAFE_ACCESS` exclusively for reading all fields in `FlutterEngineSpawnConfig`.
  - Never reject based on `struct_size < sizeof(FlutterEngineSpawnConfig)`. Older embedders with smaller struct sizes must remain fully valid, with unpopulated fields defaulting safely.
  - Do NOT bump `FLUTTER_ENGINE_VERSION` (§G.5, §G.9 Item 2).
  - Append `FlutterEngineSpawnFnPtr Spawn;` at the end of `FlutterEngineProcTable`.
  - Move `FlutterGpuAvailability` enum before `#ifndef FLUTTER_ENGINE_NO_PROTOTYPES` so it remains visible when `FLUTTER_ENGINE_NO_PROTOTYPES` is defined.
- **Layering & Scope (§A.1 I-9, I-10):**
  - All changes restricted strictly to `shell/platform/embedder/`.
  - No changes to `shell/common/`, `runtime/`, `lib/ui/`, or other embedders (Linux/Windows/macOS/iOS).
  - No Android types, no NDK headers, and no `#if defined(__ANDROID__)` in `shell/platform/embedder/`. Standard C-ABI types and opaque handles only.
- **Lifecycle & Thread Safety:**
  - `FlutterEngineSpawn` must be invoked on the platform task runner thread.
  - `EmbedderThreadHost` must be safely shared via `std::shared_ptr<EmbedderThreadHost>`.
  - Out-of-order teardown must be cleanly supported: parent engine shutting down while spawned child is alive, or child shutting down before parent. Active task runners are invalidated and thread hosts joined only when the last engine referencing the host is collected.
- **Testing & Verification (Rule 7 in `MIGRATION_LEDGER.md`):**
  - Host unit tests verifying:
    - Spawning an engine with custom entrypoint and `initial_route`.
    - Out-of-order teardown (parent first, then child; and multiple spawned children).
    - `SAFE_ACCESS` backward compatibility when passed a truncated `FlutterEngineSpawnConfig` struct size.
    - Proc table population and function pointer validation in `embedder_unittests_proctable.cc`.

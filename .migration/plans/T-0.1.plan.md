# T-0.1 Plan: Enumerate and Publish Android Embedder Test Gap

## Goal
Enumerate and publish an authoritative inventory of the testing gaps in the Android embedder (`shell/platform/android`) prior to any refactoring. This document will detail existing unit, Robolectric, and integration test coverage across twelve critical subsystems, assess test reachability (host unit, device unit, Robolectric, E2E), and produce a prioritized top-10 ranked gap list driving tasks T-0.2 through T-0.5. There is no runtime behaviour change.

## Files Touched
- `engine/src/flutter/docs/android/embedder_test_gaps.md` (new)

## Implementation Sequence
1. Conduct an exhaustive audit of:
   - Native unit tests listed in `shell/platform/android/BUILD.gn` under `flutter_shell_native_unittests`.
   - Java unit/Robolectric tests under `shell/platform/android/test/`.
   - Integration tests in `dev/integration_tests/android_engine_test/` and devicelab tasks in `dev/devicelab/`.
2. Assess and document the testing status (`tested`, `partially tested`, or `untested`) for the 12 required subsystems:
   - Surface lifecycle (`NotifyCreated`, `NotifySurfaceWindowChanged`, `NotifyDestroyed`, backgrounding)
   - Thread creation, affinity, and priority (`AndroidPlatformThreadConfigSetter`)
   - Dynamic thread merging (`AndroidExternalViewEmbedder::SupportsDynamicThreadMerging`)
   - Platform message thread affinity (`PlatformMessageHandlerAndroid::DoesHandlePlatformMessageOnPlatformThread`)
   - External texture lifetime (`ImageExternalTexture`, `SurfaceTextureExternalTexture`)
   - Vsync and frame pacing (`VsyncWaiterAndroid`)
   - App lifecycle state transitions
   - Viewport metrics (30 parameters from `FlutterJNI.nativeSetViewportMetrics`)
   - Semantics/accessibility field coverage
   - Engine spawn / `FlutterEngineGroup`
   - Deferred components
   - `DartCallbackCache` across process restarts
3. For each gap, record whether it can be exercised from:
   - Host unit test (Linux/macOS engine test)
   - On-device native unit test (`flutter_shell_native_unittests` on Android emulator/hardware)
   - Robolectric JVM test (`gradlew test` in `shell/platform/android`)
   - End-to-end / devicelab integration test (`flutter drive`, devicelab)
4. Rank the gaps by (migration risk × coverage absence) and mark the top 10 gaps, explicitly mapping them to T-0.2 through T-0.5 or recording an accepted reason.
5. Create `engine/src/flutter/docs/android/embedder_test_gaps.md` containing the complete inventory.

## Test & Verification Plan
- Pure documentation change; no source code or build configuration modified.
- Standard analysis gate verifies tool and workspace health.
- Definition of done verified: markdown document present, all 12 subsystems evaluated with explicit verdicts, top 10 ranked list mapped to downstream tasks.

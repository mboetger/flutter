**Steps (Assigned entirely inside T-0.15a):**
1. Set up Dependency Injected interfaces (`FakeSystemCommandExecutor` / `MemoryFileSystem`). Ensure tests run successfully under both `bin/cache/dart-sdk/bin/dart test` AND `bin/flutter test`.
2. Explicitly map `--task` (orchestrating which task steps apply) and `--gates` (explicit selections: `native,robolectric,host,analysis,ratchet,matrix,devicelab`) parsing variables securely in parameters establishing capabilities.
3. Provide `RealSystemCommandExecutor` explicitly leveraging `includeParentEnvironment: true`.
4. Implement core capabilities (Req 1, 3, 4, 6) generating JSON blocks explicitly parsing `commit_sha` and `parent_sha` directly from git execution natively, avoiding CLI ingestion definitively. Ensure `allPassed = false` initialized to thwart vacuous successes.
5. Rewrite CLI `args` mapping using standard `addFlag('check-artifact-sha')`. Enforce mutual exclusivity preventing spoofed dual-flag updates natively covering Req 9. Ensure `check-artifact-sha` reads JSON from the actual disk path, not CLI string.
6. Implement Smart Workspace (DR-0014) logic parsing `git status --porcelain`. Fail closed explicitly by verifying matching prefixes strictly guaranteeing `.startswith('.migration/')`. Safely block git Rename (`R`) markers ensuring sub-directories (e.g. `lib/.migration/x.cc`) are blocked correctly answering Req 2. Support `--allow-dirty` which permits executions printing `"dirty": true` gracefully.
7. Construct `--audit-stack` (Req 5) parsing backwards through the stack, validating chains. Build `--summary` generating statistical payloads safely.
8. Wire `--device-lock` ensuring explicit test protections (Req 7). This must strictly validate A.7 preconditions (e.g. `dumpsys deviceidle`). Release mechanism must perform hard device cleanup: `adb uninstall` targeted app and `adb logcat -c` on execution exit, ensuring isolated execution blocks.
9. Support clean diagnostic errors guarding unhandled `FormatException` boundaries, gracefully evaluating Defer capabilities.
10. Ensure the matrix explicitly runs the E2E verification test internally against an actively tracked directory state checking structural guarantees properly.

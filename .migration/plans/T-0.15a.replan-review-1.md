### BLOCKING FINDINGS

1. **Residual Path to Real Executables (Test Sabotage Hole)**
   The core directive of the replan demands that tests cannot be made to pass by modifying files outside `dev/tools/`. While T-0.15a Step 4 introduces `GateExecutor` to intercept gates, Steps 6 and 9 still require running `git status` and `git rev-parse`. Because these are omitted from the mock interface, the test `test('refuses to run on a dirty tree')` will invoke a REAL `git status` on the Flutter repository. To pass it, the implementer's cheapest path is to append an uncommitted file to the repo testing root outside `dev/tools/`.
   - **Resolution:** Expand the DI interface (e.g., to a general `SystemCommandExecutor`) to intercept ALL subprocess calls, including `git status` and `git rev-parse`. Explicitly ban unit tests from executing any unmocked native OS processes.

2. **`--check-artifact-sha` Bypass Vulnerability (The FileSystem Hole)**
   The plan introduces `test('--check-artifact-sha fails if code-review-*.md artifacts are missing')`. Because the plan does not define a file-system dependency injection strategy, the implementer is incentivized to take one of two failure-inducing paths: (a) read an environment variable (e.g. `TEST_DIR`) to point the tool at a mock directory, which would allow *any* future agent to bypass pipeline checks by overriding that variable; or (b) physically delete actual `.migration/` requirement files during test execution, re-introducing repo sabotage.
   - **Resolution:** Explicitly mandate the use of `package:file` (e.g. `MemoryFileSystem`) to mock disk access in unit tests. Explicitly ban any environment variable or CLI parameter that overrides the validation directory paths, guaranteeing the tool unconditionally evaluates the real repository root in production.

3. **Context Pack: Overstated Threat Model (Silent Fallback in Prose)**
   Section 7 of the Context Pack claims the new tool makes sabotage "retroactively mathematically detectable." This overstatement lulls downstream reviewers into a false sense of security. The tool fundamentally **cannot** detect if the target devicelab script is modified in the repository to execute `sleep 3600; exit 0`, nor can it detect if the `migration_verify.dart` tool itself is tampered with by the implementer to emit fake telemetry.
   - **Resolution:** Amend the Threat Model section in the Context Pack to honestly state its limitations. Explicitly record that the mechanism 1) Relies entirely on the Code Reviewer to catch modifications to the tool itself, and 2) Cannot detect internal repository sabotage of the target executable scripts.

4. **Post-Facto Metadata Schema Omissions**
   T-0.15a Step 3 correctly outlines that `RealGateExecutor` must capture STDOUT/STDERR and absolute executable paths. However, Step 5 (JSON schema creation) directs logging only "the gate's wall-clock times [and] duration metadata" into the schema. Losing the executable path and explicit exit code/log string maps in the verifiable artifact destroys the orchestrator's ability to mechanically detect spoofing.
   - **Resolution:** Update T-0.15a Step 5 to explicitly require encoding the targeted absolute path, full exit code, and execution output (or log file linkage) into the structured `T-X.Y.json` validation artifact.

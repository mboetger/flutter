  - L125-140: `PlatformViewEmbedder::HandlePlatformMessage` dispatches message to `platform_dispatch_table_.platform_message_response_callback`.

### Threading Evidence
- When `DoesHandlePlatformMessageOnPlatformThread()` is `true`:
  - Dart sends message on UI thread -> `Shell::OnEngineHandlePlatformMessage` -> `EmbedderPlatformMessageHandler::HandlePlatformMessage` -> posts task to `platform_task_runner_` -> executes on platform thread -> `platform_message_callback` invoked on platform thread.
- When `DoesHandlePlatformMessageOnPlatformThread()` is `false`:
  - Dart sends message on UI thread -> `Shell::OnEngineHandlePlatformMessage` -> `EmbedderPlatformMessageHandler::HandlePlatformMessage` -> invoked immediately on UI thread -> `platform_message_callback` invoked on UI thread.
  - The embedder can inspect `message->channel` and dispatch to a background worker pool (`BinaryMessenger.makeBackgroundTaskQueue()`) or the platform main thread.

## Part 4: Governing Decisions & Design Docs
- **DR-0020:** Embedder API configuration knob for platform message thread affinity (Blocker B-3).

- **`MIGRATION_PLAN.md` §10.1 Criterion 1:** Preserves observable behavior exactly. Conforming to `true` would alter background channel dispatch and introduce main thread contention.
- **`MIGRATION_PLAN.md` §6:** C-ABI backward and forward compatibility rules. Do not bump `FLUTTER_ENGINE_VERSION`. Use `SAFE_ACCESS`.

## Part 5: v7 Post-Mortem Analysis
- v7 did not address Blocker B-3 in the Embedder API. Instead, in `phase-6.2`, v7 attempted an ad-hoc workaround in `flutter_embedder_native.cc` using `AndroidJvmInvoker` that forced all messages to the Android main thread, breaking background channels and causing test timeouts on background `TaskQueue` plugins.
- v8 avoids this by providing an explicit, platform-agnostic configuration knob in `embedder.h` that matches Android and iOS requirements without any platform-specific code.

## Part 6: Known Traps Audit (§G.9)
- Trap 2: `FLUTTER_ENGINE_VERSION` must NOT be bumped (remains at 1).
- Trap: A boolean field where the default behavior is `true` cannot be zero-initialized safely in C without breaking recompilations. Therefore, an enum `FlutterPlatformMessageRouting` with `kFlutterPlatformMessageRoutingPlatformThread = 0` guarantees that zero-initialization preserves legacy behavior.
- Trap: Never use `struct_size < sizeof(...)` or reject truncated structs.

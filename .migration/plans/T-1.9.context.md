# T-1.9 Context: Vulkan External Textures & Backing-Store Render Targets

## 1. Problem Statement
In Flutter, external textures enable hardware-accelerated video playback, camera preview streams, and platform view composition (Virtual Displays and Texture Layer Hybrid Composition) without CPU copying.
In the Embedder API (`embedder.h`), external textures are currently supported for OpenGL (`FlutterOpenGLRendererConfig::gl_external_texture_frame_callback`) and Metal (`FlutterMetalRendererConfig::external_texture_frame_callback`).
However, `FlutterVulkanRendererConfig` has no external texture callback. As identified in Blocker B-5 (`engine/src/flutter/docs/android/embedder_external_texture_gaps.md`) and Decision Record DR-0022, when running Vulkan (including Impeller Vulkan on Android), an embedder has no C-ABI mechanism to provide external textures (`VkImage` handles imported from `AHardwareBuffer` or native streams).
Furthermore:
1. `EmbedderExternalTextureResolver` only wires OpenGL (`SHELL_ENABLE_GL`) and Metal (`SHELL_ENABLE_METAL`), lacking Vulkan external texture resolution entirely.
2. In `embedder.cc`, `kFlutterBackingStoreTypeVulkan` under Impeller currently logs `FML_LOG(ERROR) << "Unimplemented"; break;` (line 1550).
3. Embedders providing a `FlutterVulkanBackingStore` need backing-store render targets to be cleanly handled and validated when Impeller Vulkan is enabled.

Without `vulkan_external_texture_frame_callback` in `FlutterVulkanRendererConfig` and Vulkan support in `EmbedderExternalTextureResolver`, any embedder using Vulkan cannot render external textures or camera/video streams.

## 2. Constraints & Invariants
- **C-ABI Backward Compatibility (§6.1 Rule 1 & Rule 2):**
  - Define `FlutterVulkanExternalTexture` and `FlutterVulkanTextureFrameCallback` in `embedder.h`.
  - Append `vulkan_external_texture_frame_callback` to the end of `FlutterVulkanRendererConfig`.
  - In `embedder.cc`, use `SAFE_ACCESS(vulkan_config, vulkan_external_texture_frame_callback, nullptr)` to ensure embedders compiled against older header definitions do not crash.
  - Do NOT bump `FLUTTER_ENGINE_VERSION` (§G.5, §G.9 Item 2). Forward/backward compatibility is managed strictly via `struct_size` and `SAFE_ACCESS`.
- **Validation (§6.1 Rule 7):**
  - Validate external texture callbacks: texture identifiers, non-null pointers, valid dimensions, and non-null `image` handles.
  - If a callback fails or returns a null/invalid image, fail gracefully without crashing or corrupting engine state.
- **Layering & Scope (§A.1 I-9, I-10):**
  - Stage 1 is restricted strictly to the embedder layer: `shell/platform/embedder/`.
  - No Android types, no `#if defined(__ANDROID__)`, and no NDK headers in `shell/platform/embedder/` (Rule 6 in `MIGRATION_LEDGER.md`).
  - Opaque handles and standard Vulkan types only.
- **Testing & Verification (Rule 7 in `MIGRATION_LEDGER.md`):**
  - Host unit tests in `embedder_unittests` (in `embedder_vk_unittests.cc` and/or `embedder_unittests.cc`) that run on the host.
  - Coverage must verify:
    - Callback registration and invocation for Vulkan external textures.
    - Graceful handling when the callback is omitted (legacy struct size with `SAFE_ACCESS`).
    - Vulkan backing store render target validation.

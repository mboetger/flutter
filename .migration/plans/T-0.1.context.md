# T-0.1 Context Pack: Android Embedder Test Gap

## 1. Ground Truth Verification
- `shell/platform/android/BUILD.gn`:
  - `flutter_shell_native_unittests` targets: `android_context_gl_impeller_unittests.cc`, `android_image_generator_unittests.cc`, `android_shell_holder_unittests.cc`, `apk_asset_provider_unittests.cc`, `flutter_shell_native_unittests.cc`, `image_lru_unittests.cc`, `platform_view_android_jni_impl_unittests.cc`, `platform_view_android_unittests.cc`, and `android_context_gl_unittests.cc` (!slimpeller).
- `shell/platform/android/platform_view_android_unittests.cc`:
  - Only contains one DISABLED test (`DISABLED_SelectsVulkanBasedOnApiLevel`), no surface lifecycle tests.
- `shell/platform/android/android_shell_holder_unittests.cc`:
  - Tests basic shell creation and message handling; no thread priority or dynamic thread merging tests.
- `shell/platform/android/test/`:
  - Over 100 Robolectric tests for Java classes (`PlatformViewsControllerTest`, `FlutterViewTest`, `AccessibilityBridgeTest`, etc.).
- `dev/integration_tests/android_engine_test/`:
  - Integration tests for platform views (VD, TLHC, HC, HCPP), external textures (`SurfaceTexture`, `SurfaceProducer`).

## 2. Current Code & Gaps Identified
- Surface lifecycle: `NotifyCreated`, `NotifySurfaceWindowChanged`, `NotifyDestroyed` in `PlatformViewAndroid` have no native C++ test coverage.
- Threading & priority: `AndroidPlatformThreadConfigSetter` sets IO thread to `kNormal` (vs default `kBackground`); dynamic thread merging in `AndroidExternalViewEmbedder` has no native test.
- Viewport metrics: `FlutterJNI.nativeSetViewportMetrics` 30 parameters not asserted natively in `flutter::ViewportMetrics`.
- Platform message affinity: `PlatformMessageHandlerAndroid::DoesHandlePlatformMessageOnPlatformThread()` returns `false`, while Embedder API returns `true`.

## 3. Baseline Numbers
- Baseline will be formally captured in T-0.12. T-0.1 establishes the gap inventory prior to test characterization.

## 4. Governing Plan Sections

## 5. What v7 Did & Lessons Learned
- In v7, lack of characterization tests allowed platform views (`external_view_embedder.cc`, etc.) and external texture implementations to be removed without CI test failures because the tests were deleted along with the code and never wired to CI.
- T-0.1 prevents this by cataloging the test gap and establishing the required tests before any refactoring.

## 6. Known Traps (§G.9)
- Do not assume Robolectric coverage guarantees native C++ correctness.
- Do not assume integration tests cover edge cases or native resource leaks (e.g. ASan teardown).

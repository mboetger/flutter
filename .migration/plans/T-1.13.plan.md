---

## 1. Goal & Observable Behaviour Change
- **Goal:** Extend the Flutter Embedder C-API with a platform message routing configuration knob (`FlutterPlatformMessageRouting`), allowing embedders (such as Android and iOS) to receive platform messages directly on the engine calling thread (UI thread) without an automatic hop to the platform task runner. This resolves Blocker B-3, preserving zero-contention background `TaskQueue` execution and matching the native threading behavior of Android and iOS.
- **Observable Behaviour Change:** None for existing embedders (zero-initialized `FlutterProjectArgs` defaults to legacy platform thread dispatch). When `kFlutterPlatformMessageRoutingCallingThread` is opted in, embedders receive incoming platform messages on the engine UI thread rather than the platform thread.

## 3. Implementation Sequence
1. **Header Additions (`embedder.h`):**
   ```c
   typedef enum {
     kFlutterPlatformMessageRoutingPlatformThread = 0,
     kFlutterPlatformMessageRoutingCallingThread = 1,
   } FlutterPlatformMessageRouting;
   ```
   Append to `FlutterProjectArgs`:
   ```c
   /// Specifies the routing behavior for incoming platform messages delivered
   /// from the Dart application.
   ///
   /// If zero-initialized or set to
   /// `kFlutterPlatformMessageRoutingPlatformThread`, the engine routes all
   /// incoming platform messages to the platform task runner before invoking
   /// `platform_message_callback`.
   ///
   /// If set to `kFlutterPlatformMessageRoutingCallingThread`, the engine
   /// invokes `platform_message_callback` directly on the thread on which the
   /// message arrived (typically the UI task runner).
   FlutterPlatformMessageRouting platform_message_routing;
   ```
2. **Platform View Embedder Updates (`platform_view_embedder.{h,cc}`):**
   - In `PlatformDispatchTable`: add `bool does_handle_platform_messages_on_platform_thread = true;`.
   - In `EmbedderPlatformMessageHandler`: pass `platform_dispatch_table_.does_handle_platform_messages_on_platform_thread` to constructor.
   - Return stored boolean from `DoesHandlePlatformMessageOnPlatformThread()`.
   - In `HandlePlatformMessage`: if `does_handle_platform_messages_on_platform_thread_` is true, post to `platform_task_runner_`; otherwise execute `parent->HandlePlatformMessage(std::move(message))` directly.
3. **Engine C-API Binding (`embedder.cc`):**
   - In `CreatePlatformDispatchTable`:
     ```cpp
     auto routing = SAFE_ACCESS(
         args, platform_message_routing,
         kFlutterPlatformMessageRoutingPlatformThread);
     platform_dispatch_table.does_handle_platform_messages_on_platform_thread =
         (routing == kFlutterPlatformMessageRoutingPlatformThread);
     ```
4. **Test Harness & Unit Tests:**
   - Update `EmbedderConfigBuilder` to set `platform_message_routing`.
   - Add unit tests in `embedder_unittests.cc`:
     - `PlatformMessageRoutingDefaultPlatformThread`: asserts `platform_message_callback` is invoked on the platform task runner.
     - `PlatformMessageRoutingCallingThread`: asserts `platform_message_callback` is invoked directly on the UI task runner.
     - `PlatformMessageRoutingTruncatedStruct`: asserts truncated struct safely defaults to platform thread routing.

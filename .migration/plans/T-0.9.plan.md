# T-0.9 Plan: Dependency Ratchet Tooling

## Goal
Implement `engine/src/flutter/tools/android_embedder_deps.py` and commit `engine/src/flutter/tools/android_embedder_deps_baseline.json`. The ratchet script must inspect all C/C++ targets across `shell/platform/android/BUILD.gn` and its subdirectories, calculate internal-engine GN deps, internal-engine `#include`s, and `// nogncheck` occurrences, compare against the baseline on `--check` (failing non-zero on any regression), support `--update-baseline`, print human-readable summary diff tables, and integrate with `migration_verify.dart` under the `ratchet` gate.

## Files Touched
- `engine/src/flutter/tools/android_embedder_deps.py` (new executable script)
- `engine/src/flutter/tools/android_embedder_deps_baseline.json` (new committed baseline)

## Implementation Sequence
1. Design `android_embedder_deps.py`:
   - Engine path resolution: automatically discover repo root and `engine/src/flutter` from `__file__`.
   - GN target discovery: parse `shell/platform/android/BUILD.gn` and subdirectories (`context`, `external_view_embedder`, `jni`, `platform_view_android_delegate`, `surface`).
   - Dep categorization:
     Allowed prefixes: `//flutter/fml`, `//flutter/assets`, `//flutter/common`, `//flutter/shell/platform/embedder`, `//flutter/shell/platform/android`, `:`.
     Internal engine deps: any dep starting with `//flutter/` that is not in the allowed list.
   - Header include categorization:
     Allowed prefixes: `flutter/fml/`, `flutter/assets/`, `flutter/common/`, `flutter/shell/platform/embedder/embedder.h`, `flutter/shell/platform/android/`.
     Internal engine includes: any include of form `#include <flutter/...>` or `#include "flutter/..."` not matching the allowed list.
   - Nogncheck detection: scan GN files and source files for occurrences of `nogncheck`.
   - Output formatting: generate clear markdown/ASCII table with target name, internal deps, internal includes, and nognchecks.
   - Modes:
     `--check`: compare current against `android_embedder_deps_baseline.json`; return 0 if counts <= baseline, 1 if any count increased.
     `--update-baseline`: record current counts into `android_embedder_deps_baseline.json`.
2. Generate baseline:
   - Run with `--update-baseline` to establish the authoritative baseline for master.
3. Verification:
   - Run `--check` and confirm clean exit 0.
   - Inject synthetic violation, confirm failure with non-zero exit code, and revert.
   - Run `migration_verify.dart --task T-0.9 --gates analysis,ratchet`.

# Plan Review: T-1.11 (FlutterEngineSpawn in Embedder C-API)

## Review Details
- **Task:** T-1.11
- **Reviewer:** Senior Software Engineer (Pair Programmer / Reviewer)
- **Status:** **APPROVE**
- **Date:** 2026-09-16

## Evaluation Against Constraints & Guidelines
1. **Info-Struct Pattern & C-ABI Compatibility:**
   - The plan faithfully implements the info-struct pattern requested in design doc review c10/c11 (Loïc / Chris Bracken) by introducing `FlutterEngineSpawnConfig` with `size_t struct_size`, `entrypoint`, `library_path`, `initial_route`, `argc`, `argv`, `user_data`, `custom_args`, and `custom_renderer_config`.
   - Forward and backward binary compatibility is strictly preserved: all fields are read via `SAFE_ACCESS`. The hard comparison `struct_size < sizeof(...)` which caused the regression in v7 is explicitly banned and replaced with `SAFE_ACCESS(config, ...)`.
   - `FLUTTER_ENGINE_VERSION` remains at `1` and is not modified.
   - `FlutterGpuAvailability` enum definition is relocated before `#ifndef FLUTTER_ENGINE_NO_PROTOTYPES` to maintain type visibility for proc-table consumers.
   - The proc table is cleanly extended at the end with `FlutterEngineSpawnFnPtr Spawn;`.

2. **Layering & Scope (Invariant I-9 & I-10):**
   - The implementation is strictly confined to `shell/platform/embedder/`.
   - No modifications are made to `shell/common/`, `runtime/`, `lib/ui/`, or other platform embedders.
   - Zero Android types, NDK headers, or `#if defined(__ANDROID__)` guards are introduced.

3. **Lifecycle & Thread Safety:**
   - Thread safety during multi-engine teardown is thoroughly addressed: `EmbedderThreadHost` is managed via `std::shared_ptr<EmbedderThreadHost>`.
   - A mutex-guarded `use_count()` check ensures that only the final surviving engine tears down active runners and shuts down threads, preventing use-after-free or dangling runner issues during out-of-order engine destruction.

4. **Testing Strategy:**
   - The test plan covers basic spawn execution, custom entrypoint with initial route, out-of-order teardown (parent destroyed before child), backward compatibility with truncated struct sizes, and proc table registration.

**Decision: APPROVE.** Proceed to implementation.

# Context: Task T-0.11 — Composition Conformance Harness

## Problem Statement
In previous migration attempts (v7), 1,848 lines of platform view tests and implementation files (`external_view_embedder.cc`, `surface_pool.cc`, `surface_texture_external_texture.cc`) were deleted unnoticed because the test harness inferred test targets dynamically from directory globs (`lib/**_main.dart`) rather than enforcing an explicit contract. When files were deleted or skipped, the runner simply ran fewer tests without failing.

Task T-0.11 transforms `dev/bots/suite_runners/run_android_engine_tests.dart` into an unbreakable composition conformance gate:
1. Replaces path-glob inference with an explicit `CompositionMode` enum registry:
   - `virtualDisplay` (VD)
   - `textureLayerHybrid` (TLHC)
   - `hybrid` (HC)
   - `hcpp` (Hybrid Composition++)
   - `surfaceTexture` (SurfaceTexture external texture)
   - `surfaceProducer` (SurfaceProducer external texture)
2. Enforces an empty-mode assertion: if any mode resolves to 0 mains or runs 0 tests in a supported backend configuration, the shard immediately fails naming the mode.
3. Encodes the HCPP Vulkan-only constraint with an explicit `unsupported(reason: ...)` declaration rather than an opaque conditional.
4. Adds coverage for the GLES HCPP fallback path: verifies that when an app requests HCPP on OpenGLES, it falls back to legacy platform views (`EXPECT_HCPP=false`) via `upgrade_legacy_pv_types_main.dart`.
5. Plumbs the `androidEmbedderApi` flag axis (`--android-embedder-api` / `--no-android-embedder-api`), inert until the flag is added in Stage 1.
6. Emits a machine-readable summary (`composition_matrix_results.json`) tracking results by mode, backend, and flag state.

## Governing Invariants & Principles
- **I-1 (No silent fallbacks):** Explicitly declared supported/unsupported configurations; fallback paths are tested.
- **I-2 & I-3 (No weakening of tests/assertions):** All 4 modes and 2 external texture paths must be exercised.
- **I-11 (All composition modes preserved):** Harness ensures no composition mode can be deleted or skipped silently.
- **I-12 (Continuous E2E verification):** Runs at every stage boundary.

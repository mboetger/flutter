# T-0.2 Context Pack: Surface Lifecycle Characterization Tests

## 1. Ground Truth Verification
- `shell/platform/android/BUILD.gn`:
  - `flutter_shell_native_unittests` targets currently do not include any surface lifecycle test.
  - Adding `platform_view_android_surface_lifecycle_unittests.cc` to `flutter_shell_native_unittests` sources.
- `shell/platform/android/platform_view_android.cc`:
  - `NotifyCreated(native_window)`: Runs on platform thread, synchronously posts to raster thread to call `android_surface_->SetNativeWindow(native_window, jni_facade_)`, waits on `fml::AutoResetWaitableEvent latch`, then calls `PlatformView::NotifyCreated()`.
  - `NotifySurfaceWindowChanged(native_window)`: Runs on platform thread, synchronously posts to raster thread to call `android_surface_->TeardownOnScreenContext()`, `android_surface_->SetNativeWindow(native_window, jni_facade_)`, waits on latch, then calls `PlatformView::ScheduleFrame()`.
  - `NotifyDestroyed()`: Runs on platform thread, calls `PlatformView::NotifyDestroyed()`, then synchronously posts to raster thread to call `android_surface_->TeardownOnScreenContext()`, waiting on latch.
  - `CreateRenderingSurface()`: Runs on raster thread, called from `PlatformView::NotifyCreated()`, calls `android_surface_->CreateGPUSurface()`.

## 2. Current Code & Subsystem Dynamics
- `AndroidNativeWindow`: Can be instantiated with `fml::MakeRefCounted<AndroidNativeWindow>(nullptr, /*is_fake_window=*/true)` for testing without real hardware display.
- Thread affinity:
  - `NotifyCreated`, `NotifySurfaceWindowChanged`, `NotifyDestroyed` are invoked on Platform thread.
  - The surface operations (`SetNativeWindow`, `TeardownOnScreenContext`, `CreateGPUSurface`) execute on Raster thread.
  - Synchronous coordination is achieved via `fml::AutoResetWaitableEvent` latches.
- Idempotency & edge cases:
  - Calling `NotifyCreated` when already created (`android_surface_` already has window).
  - Calling `NotifyDestroyed` when already destroyed (`android_surface_` teardown called twice).
  - Window change during frame scheduling.
  - Teardown while raster thread has tasks queued.

# Context: T-3.6 — Replace `UnregisterTexture` / `MarkTextureFrameAvailable` with Embedder API Seams behind Flag

## Problem Statement
In the legacy Android embedding, external texture notifications (unregistration and frame availability) arrive via JNI (`nativeUnregisterTexture`, `nativeMarkTextureFrameAvailable`) to `PlatformViewAndroid` which forwards to `platform_view_->UnregisterTexture(id)` and `platform_view_->MarkTextureFrameAvailable(id)`.
In the Flutter Embedder API, these operations are handled by:
- `FlutterEngineUnregisterExternalTexture(engine, texture_id)`
- `FlutterEngineMarkExternalTextureFrameAvailable(engine, texture_id)`

## Scope of Changes
1. `engine/src/flutter/shell/platform/android/platform_view_android.h`:
   - Declare `FlutterEngineResult UnregisterExternalTexture(int64_t texture_id);`
   - Declare `FlutterEngineResult MarkExternalTextureFrameAvailable(int64_t texture_id);`
2. `engine/src/flutter/shell/platform/android/platform_view_android.cc`:
   - Update `UnregisterTexture(int64_t texture_id)` and `MarkTextureFrameAvailable(int64_t texture_id)` to branch on `android_embedder_api_`.
   - On flag-on path: emit `TRACE_EVENT1(..., "embedder_api")` and route through the new seams.
   - On legacy path: emit `TRACE_EVENT1(..., "legacy")` and forward to `external_texture_adapter_` / `platform_view_`.
   - Implement `UnregisterExternalTexture` and `MarkExternalTextureFrameAvailable`.
3. `engine/src/flutter/shell/platform/android/platform_view_android_unittests.cc`:
   - Update `FakePlatformViewDelegate` to capture unregister and mark frame available calls.
   - Add unit tests verifying legacy dispatch, embedder dispatch, direct seam invocation, and argument validation.

## Non-goals
- Full composition mode migration (scheduled for T-3.T1 - T-3.T6).
- Modifying Java-side `TextureRegistry` in this task.

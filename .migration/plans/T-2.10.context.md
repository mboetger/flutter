# Context: T-2.10 — Introduce an External Texture Seam Shaped like FlutterEngineRegisterExternalTexture

## Context & Architecture
In the Android embedder, external textures support:
1. Platform view composition in Virtual Display (VD) and Texture Layer Hybrid Composition (TLHC) modes.
2. Hardware-accelerated media rendering for plugins (`video_player`, `camera`, `google_maps_flutter`, `webview_flutter`).

External textures are represented natively by two hierarchies:
- `SurfaceTextureExternalTexture` (`SurfaceTextureExternalTextureGLSkia`, `SurfaceTextureExternalTextureGLImpeller`, `SurfaceTextureExternalTextureVKImpeller`)
- `ImageExternalTexture` (`ImageExternalTextureGLSkia`, `ImageExternalTextureGLImpeller`, `ImageExternalTextureVKImpeller`)

In Stage 3, external textures will be registered through the Embedder API's texture management entry points:
- `FlutterEngineRegisterExternalTexture`
- `FlutterEngineUnregisterExternalTexture`
- `FlutterEngineMarkExternalTextureFrameAvailable`

To prepare for Stage 3 while preserving 100% behavioral equivalence across all rendering backends in Stage 2:
- Introduce `AndroidExternalTextureAdapter` as an external texture seam in front of `SurfaceTextureExternalTexture` and `ImageExternalTexture`.
- Provide methods shaped like `FlutterEngineRegisterExternalTexture`, `FlutterEngineUnregisterExternalTexture`, and `FlutterEngineMarkExternalTextureFrameAvailable`.
- Keep both registration paths fully functional:
  - Java/JNI `RegisterSurfaceTexture` and `RegisterImageTexture`.
  - Embedder API `RegisterExternalTexture(texture_id)`.
- Wire `PlatformViewAndroid` to delegate texture operations to `AndroidExternalTextureAdapter`.
- Neither `SurfaceTextureExternalTexture` nor `ImageExternalTexture` is deleted (I-11).
- No file under `external_view_embedder/` is deleted (I-11).

# T-1.6 Context: Pointer Data Gaps (tilt, orientation, radius, distance, size, embedder_id)

## 1. Problem Statement
The Embedder API (`embedder.h`) defines `FlutterPointerEvent`, which embedders use to dispatch pointer events to the Flutter engine via `FlutterEngineSendPointerEvent`.
Currently, `FlutterPointerEvent` lacks essential stylus and touch geometry attributes that are present in `flutter::PointerData` (`engine/src/flutter/lib/ui/window/pointer_data.h`) and delivered by platform input subsystems (such as Android's `AndroidTouchProcessor.java` and iOS's `FlutterViewController.mm`):
1. `tilt`: Tilt angle of the pointer/stylus in radians (0 <= tilt <= pi/2), relative to perpendicular axis.
2. `orientation`: Orientation angle of the pointer/stylus in radians (-pi < orientation <= pi), relative to positive y-axis.
3. `radius_major`: Radius of the touch contact ellipse along the major axis in physical pixels.
4. `radius_minor`: Radius of the touch contact ellipse along the minor axis in physical pixels.
5. `radius_min`: Minimum bound of the contact ellipse radius in physical pixels.
6. `radius_max`: Maximum bound of the contact ellipse radius in physical pixels.
7. `distance`: Distance of the pointer from the contact surface in physical pixels (e.g. for hovering styluses).
8. `distance_max`: Maximum distance of the pointer from the contact surface in physical pixels.
9. `size`: Normalized touch contact area in the range [0.0, 1.0].
10. `embedder_id`: Embedder-provided identifier for event tracking and correlated motion event dispatch (e.g. Android `motionEventId`). Note that `embedder.cc` currently hardcodes `pointer_data.embedder_id = 0` with a comment noting it is currently only used on Android.

Without these fields in `FlutterPointerEvent`, drawing applications, handwriting recognition, stylus pressure/tilt shading, contact palm rejection, and hover distance effects in Flutter applications running on top of embedders cannot receive stylus tilt, orientation, or contact ellipse geometry.

## 2. Constraints & Invariants
- **C-ABI Backward Compatibility (§6.1 Rule 1 & Rule 2):**
  - All new fields must be strictly appended to `FlutterPointerEvent`.
  - In `FlutterEngineSendPointerEvent` (`embedder.cc`), all field accesses must use `SAFE_ACCESS(current, member, fallback)` based on `current->struct_size` to preserve compatibility with embedders passing older struct sizes.
  - Existing struct members cannot be moved, resized, or reordered.
  - `FLUTTER_ENGINE_VERSION` must NOT be bumped (§G.5, §G.9 Item 2). Forward compatibility is managed exclusively via `struct_size` and `SAFE_ACCESS`.
- **Layering & Scope (§A.1 I-9, I-10):**
  - All modifications are strictly within the embedder API layer: `shell/platform/embedder/`.
  - No Android code or Android platform files (`shell/platform/android/`) may be touched in Stage 1. Android consumers will adopt these fields in Stage 3.
  - No Android-specific naming or assumptions in shared embedder code; concepts are platform-agnostic and match `PointerData` / framework `PointerEvent`.
- **Testing & Verification:**
  - Automated host unit tests in `embedder_unittests.cc` asserting that every appended field in `FlutterPointerEvent` is faithfully forwarded into the dispatched `PointerDataPacket` with non-default values and default fallbacks.

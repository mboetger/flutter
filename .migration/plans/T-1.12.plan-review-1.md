# Plan Review: T-1.12 — Custom Task Runners & Thread Priority Setter

- **Reviewer:** Plan Reviewer (Embedder API & Core Engine Architecture)
- **Date:** 2026-09-16
- **Verdict:** **APPROVE**

## 1. Architectural & Safety Evaluation
The plan for T-1.12 directly addresses the technical requirements established in `MIGRATION_PLAN.md` §1.12 and `MIGRATION_LEDGER.md` §T-0.3 / §T-1.12 / §T-2.5:

1. **Resolution of IO Thread Priority Discrepancy:**
   - In Stage 0 (T-0.3), characterization tests established that Android natively configures the IO thread to `fml::Thread::ThreadPriority::kNormal` (nice 0), while `EmbedderThreadHost` has historically hardcoded `kBackground` (nice 10).
   - The plan introduces `io_thread_priority` in `FlutterCustomTaskRunners`, allowing embedders to specify `kNormal` (or any custom priority level). When zero-initialized by older embedders, it defaults safely to `kBackground`, preserving 100% backward compatibility.
   - Furthermore, the plan introduces `io_task_runner` to `FlutterCustomTaskRunners`, granting embedders full task runner delegation for IO tasks when desired.

2. **C-ABI Backward and Forward Compatibility (§6.1):**
   - Struct extensions to `FlutterTaskRunnerDescription` and `FlutterCustomTaskRunners` are strictly append-only.
   - All struct accesses are guarded by `SAFE_ACCESS`. Hard struct size checks (`struct_size < sizeof(...)` or `struct_size < offsetof(...)`) are strictly avoided, preventing the regression seen in v7.
   - No preprocessor-conditional struct members (`#if UINTPTR_MAX...`) are added, preserving ABI portability.
   - `FLUTTER_ENGINE_VERSION` remains at `1` per upstream invariant.

3. **Contextual Thread Priority Setters:**
   - Adds `FlutterThreadPrioritySetterWithUserData` and `user_data` to both `FlutterTaskRunnerDescription` and `FlutterCustomTaskRunners`, eliminating brittle global state and enabling embedders to receive contextual handles during priority changes.
   - Integrates runtime priority updates via `EmbedderTaskRunner::SetThreadPriority`, ensuring priority changes can be posted and handled asynchronously on the appropriate thread.

4. **Zero Android Contamination (I-10):**
   - All types and signatures use standard C-ABI primitives and enums in `embedder.h`. No Android types or preprocessor checks are introduced into shared embedder code.

5. **Test Strategy:**
   - The test plan is thorough and non-Android host-runnable (`embedder_unittests.cc`), covering custom IO runner task execution, per-runner priority setters with/without user data, engine-managed priority configuration, the IO thread priority discrepancy fix, dynamic runtime priority changes, and truncated struct compatibility.

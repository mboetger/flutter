## 2. Documented Falsification Attempts

### Falsification Attempt 1: Infinite Recursion Risk Between PlatformViewAndroid and PlatformViewEmbedder
- **Hypothesis:** If `PlatformViewEmbedder`'s dispatch table callbacks invoke `PlatformViewAndroid` virtual methods (which in turn delegate back to `platform_view_->Method(...)`), execution will enter infinite mutual recursion and cause a stack overflow.
- **Investigation:** In the proposed design, `PlatformDispatchTable` callbacks in `AndroidShellHolder` do NOT call `PlatformViewAndroid` methods. Instead, they invoke `jni_facade_->...` directly (e.g. `jni_facade->FlutterViewUpdateSemantics(...)`). Therefore, when `PlatformViewAndroid::UpdateSemantics` delegates to `platform_view_->UpdateSemantics`, `PlatformViewEmbedder` executes the dispatch table callback, which directly calls `jni_facade_`. There is no loop back to `PlatformViewAndroid`.
- **Result:** Falsified. The callback routing terminates at the JNI boundary with zero recursion.

### Falsification Attempt 2: Include Ratchet Violation When Adding `platform_view_embedder.h`
- **Hypothesis:** Adding `#include "flutter/shell/platform/embedder/platform_view_embedder.h"` to `android_shell_holder.cc` will increase `flutter_shell_native_src` internal includes from 98 to 99, failing the `android_embedder_deps.py --check` ratchet gate.
- **Investigation:** In `android_shell_holder.cc`, `#include "flutter/lib/ui/painting/image_generator_registry.h"` is present but completely unreferenced (0 usages in the file). By pruning `image_generator_registry.h` (-1 internal include) in the same commit as adding `platform_view_embedder.h` (+1 internal include), the include count remains exactly 98, which satisfies `<= baseline` (98).
- **Result:** Falsified. Net internal includes count is 0, passing the ratchet check cleanly.

### Falsification Attempt 3: GPU Pipeline Disruption via Software Rasterizer Fallback
- **Hypothesis:** Constructing `PlatformViewEmbedder` with a software surface or null surface will cause `PlatformViewAndroid::CreateRenderingSurface()` and `GetImpellerContext()` to return software or null surfaces, breaking Vulkan/OpenGL Impeller and failing characterization tests.
- **Investigation:** In `PlatformViewAndroid`, surface, compositor, and vsync creation methods (`CreateRenderingSurface`, `CreateExternalViewEmbedder`, `GetImpellerContext`, `CreateVSyncWaiter`) prioritize the native Android GPU pipeline (`android_surface_`, `android_context_`, `AndroidExternalViewEmbedderWrapper`, `VsyncWaiterAndroid`) whenever the native surface is active. The `PlatformViewEmbedder` delegate handles platform dispatch callbacks (semantics, messaging, locale, fonts, restart) while surface lifecycle extraction is properly deferred to T-2.7 and T-2.9.
- **Result:** Falsified. Android GPU rendering and platform views remain 100% untouched and functional.

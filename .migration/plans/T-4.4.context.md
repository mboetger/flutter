# Context: T-4.4 — Verify the Opt-Out Still Restores the Legacy Path Exactly

## Problem Statement
Task T-4.3 established the public default of `--android-embedder-api` and formalized the `--no-android-embedder-api` opt-out switch.
Before deleting the legacy implementation in T-4.5, task T-4.4 must verify that explicitly requesting the opt-out (`--no-android-embedder-api` or `android_embedder_api = false`) restores the exact pre-migration legacy behavior captured in task T-0.12 (`engine/src/flutter/docs/android/embedder_migration_baseline.md`).
This proves that the legacy path remained untouched throughout Stage 3 and Stage 4, and that the emergency fallback is genuine.

## Scope of Changes
1. `engine/src/flutter/docs/android/embedder_migration_opt_out_verification.md`:
   - Document full parity comparison of all 21 composition integration test mains between `--no-android-embedder-api` and the T-0.12 baseline.
   - Document Devicelab correctness and performance comparisons.
   - Verify trace event routing (`path: legacy`) across all PlatformViewAndroid and AndroidShellHolder seams when the opt-out flag is set.
   - Disclose prototype limitations.
2. `docs/platforms/android/embedder-api-migration/MIGRATION_LEDGER.md`:
   - Document T-4.4 status and completion of prototype opt-out verification gate.

## Non-goals
- Deleting legacy code (scheduled for T-4.5).

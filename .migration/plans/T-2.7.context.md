# Context: T-2.7 — Extract Surface Lifecycle into the Shape Decided by T-0.7

## Context & Architecture
In the legacy Android embedder, `PlatformViewAndroid` tightly couples surface lifecycle management with raster thread synchronization:
- `NotifyCreated`, `NotifySurfaceWindowChanged`, and `NotifyDestroyed` synchronize with `AndroidSurface` (`SetNativeWindow`, `TeardownOnScreenContext`) on the raster task runner via waitable latches (`fml::AutoResetWaitableEvent`).
- They also drive first-frame callback installation (`InstallFirstFrameCallback`) and frame scheduling (`ScheduleFrame`).
- In T-0.7 and T-1.2, the Embedder API canonical surface and renderer availability lifecycle was established:
  - `FlutterEngineNotifySurfaceCreated(engine, view_id)`
  - `FlutterEngineNotifySurfaceDestroyed(engine, view_id)`
  - `FlutterEngineSetGpuAvailability(engine, availability)` using `FlutterGpuAvailability` (`kAvailable`, `kFlushAndMakeUnavailable`, `kUnavailable`).

In Stage 3, `PlatformViewAndroid` will call Embedder API functions for surface lifecycle events. To prepare for this while preserving 100% behavioral equivalence in Stage 2:
- Extract surface lifecycle and raster-thread synchronization into a standalone unit (`AndroidSurfaceLifecycle`).
- `AndroidSurfaceLifecycle` exposes the canonical surface lifecycle methods (`NotifyCreated`, `NotifySurfaceWindowChanged`, `NotifyDestroyed`, `NotifyChanged`, `SetGpuAvailability`, `IsSurfaceAvailable`).
- `PlatformViewAndroid` owns an `AndroidSurfaceLifecycle` instance and delegates surface lifecycle calls to it.

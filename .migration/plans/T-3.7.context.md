# Context: T-3.7 — Replace `Shell::Create` / `ThreadHost` with FlutterEngine Lifecycle Seams behind Flag

## Problem Statement
In the legacy Android embedding, engine initialization and launch are performed through direct `Shell::Create` and `shell_->RunEngine` invocations inside `AndroidShellHolder`.
In the standard Flutter Embedder API, engine lifecycle is controlled via:
- `FlutterEngineInitialize`
- `FlutterEngineRun` (or `FlutterEngineRunInitialized`)

## Scope of Changes
1. `engine/src/flutter/shell/platform/android/android_shell_holder.h`:
   - Declare public methods `InitializeEngine()` and `RunEngine(...)` returning `FlutterEngineResult`.
2. `engine/src/flutter/shell/platform/android/android_shell_holder.cc`:
   - Update `AndroidShellHolder` constructor to branch on `settings_.android_embedder_api`.
   - On flag-on path: emit `TRACE_EVENT1(..., "embedder_api")` and route through `InitializeEngine()`.
   - On legacy path: emit `TRACE_EVENT1(..., "legacy")` and execute legacy creation.
   - Update `Launch(...)` to branch on `settings_.android_embedder_api`.
   - On flag-on path: emit `TRACE_EVENT1(..., "embedder_api")` and route through `RunEngine(...)`.
   - On legacy path: emit `TRACE_EVENT1(..., "legacy")` and execute legacy launch.
   - Implement `InitializeEngine()` and `RunEngine(...)`.
3. `engine/src/flutter/shell/platform/android/android_shell_holder_unittests.cc`:
   - Add unit tests verifying legacy initialization, embedder API initialization, direct initialization seam, and direct run seam.

## Non-goals
- Engine spawning migration (scheduled for T-3.8).
- Composition mode migrations (scheduled for T-3.T1 - T-3.T6).

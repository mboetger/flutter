## 1. Problem Statement & Motivation
In T-1.18a, the public C-ABI types and proc table functions for dynamic raster thread merging were added to `embedder.h` and `embedder.cc`. However, the engine external view embedder (`EmbedderExternalViewEmbedder`) does not yet implement the virtual overrides required by the rasterizer to support dynamic thread merging:
1. `SupportsDynamicThreadMerging()` currently defaults to `false` in `ExternalViewEmbedder`.
2. `PostPrerollAction()` defaults to returning `PostPrerollResult::kSuccess` without forwarding to embedders.
3. `BeginFrame()` and `EndFrame()` do not forward lifecycle notifications to embedders.
4. `InferExternalViewEmbedderFromArgs` in `embedder.cc` does not parse dynamic thread merging parameters or pass them to `EmbedderExternalViewEmbedder`.

Without these overrides and wiring, the engine cannot create a `RasterThreadMerger` when dynamic merging is requested, nor can embedders lease the platform thread during Hybrid Composition (HC).

---

## 2. Technical Solution
1. **Shared Merger Struct:**
   Define `struct _FlutterRasterThreadMerger { fml::RefPtr<fml::RasterThreadMerger> merger; };` in `embedder_external_view_embedder.h` so that both `embedder.cc` and `embedder_external_view_embedder.cc` share the identical layout.

2. **`EmbedderExternalViewEmbedder` Overrides:**
   - Extend constructor to accept:
     `bool supports_dynamic_thread_merging = false`
     `FlutterPostPrerollCallback post_preroll_callback = nullptr`
     `FlutterCompositorFrameCallback begin_frame_callback = nullptr`
     `FlutterCompositorFrameCallback end_frame_callback = nullptr`
     `void* user_data = nullptr`
   - `SupportsDynamicThreadMerging()`: returns `supports_dynamic_thread_merging_`.
   - `PostPrerollAction(merger)`: Wraps `raster_thread_merger` into `_FlutterRasterThreadMerger` on the stack, constructs `FlutterFrameThreadingInfo`, invokes `post_preroll_callback_`, and translates `FlutterPostPrerollResult` to `PostPrerollResult`.
   - `BeginFrame(context, merger)`: Calls `Reset()`. If `begin_frame_callback_` is set, constructs `FlutterFrameThreadingInfo` and dispatches notification.
   - `EndFrame(should_resubmit_frame, merger)`: If `end_frame_callback_` is set, constructs `FlutterFrameThreadingInfo` and dispatches notification.

3. **`embedder.cc` Wiring (`InferExternalViewEmbedderFromArgs`):**
   - Directly `#include "flutter/shell/platform/embedder/embedder_external_view_embedder.h"`.
   - Remove duplicate `struct _FlutterRasterThreadMerger` definition.
   - Extract `supports_dynamic_thread_merging`, `post_preroll_callback`, `begin_frame_callback`, and `end_frame_callback` via `SAFE_ACCESS`.
   - Enforce Invariant I-1: If `supports_dynamic_thread_merging` is true and `post_preroll_callback` is null, fail initialization immediately with `kInvalidArgument`.
   - Forward callbacks and `compositor->user_data` to `EmbedderExternalViewEmbedder`.

## 3. Invariants & Safety
- **`FLUTTER_ENGINE_VERSION` Invariant:** Kept at 1 (§G.5/G.9).
- **I-1 No silent fallbacks:** Missing required `post_preroll_callback` when dynamic merging is requested immediately fails initialization with `kInvalidArgument`.
- **I-7 Diff cap:** Well under the 1000-line change cap (~80 lines total).
- **I-10 No Android in embedder:** Uses generic C-ABI types only; zero Android-specific headers or symbols.
- **Inertness:** Zero-initialization guarantees `supports_dynamic_thread_merging = false` for all existing desktop and iOS embedders.

## 1. Problem Statement & Motivation
`FlutterJNI.getBitmap()` backs `FlutterView` bitmap capture, used by debug tooling, automated testing, and integration tests.
Historically, this path reached directly into core engine internals:
`FlutterJNI.getBitmap()` → `AndroidShellHolder::Screenshot` → `flutter::Shell::Screenshot` → `flutter::Rasterizer::ScreenshotLastLayerTree`.

In the Embedder API migration:
- `AndroidShellHolder` is migrating away from `flutter::Shell` to wrap `FlutterEngine` (the public embedder C-API).
- A previous migration attempt added `FlutterEngineScreenshot` and `FlutterEngineFreeScreenshot` (+563 lines) to `embedder.h`, but never invoked them, stubbing `FlutterJNI.getBitmap()` to return `nullptr` and silently breaking screenshotting.
- Per the architectural decision recorded in `MIGRATION_LEDGER.md` and `DR-0023`, **screenshot capture must NOT enter `embedder.h`**. It is a platform-specific debug/test affordance.
- macOS already captures screenshots directly from its platform-owned surface (`IOSurfaceRef`) without an engine API (`FlutterEngine.mm:1450-1522`). Android must implement the equivalent platform-owned approach, decoupling `Rasterizer` entirely.

## 2. Technical Solution
1. **`AndroidSurface` Interface & Implementations:**
   - Define `AndroidSurface::Screenshot` struct containing `sk_sp<SkData> data` and `DlISize frame_size`.
   - Add virtual method `AndroidSurface::Screenshot()` in `surface/android_surface.h` (defaulting to empty screenshot in `surface/android_surface.cc`).
   - Implement `AndroidSurfaceSoftware::Screenshot()`: reads pixels directly from `sk_surface_` via `readPixels(...)`.
   - Implement `AndroidSurfaceGLSkia::Screenshot()`: binds `onscreen_surface_`, retrieves dimensions via `GetSize()`, executes `glReadPixels(...)`, and vertically flips rows to match top-down Android bitmap layout.
   - Implement `AndroidSurfaceGLImpeller::Screenshot()`: binds `onscreen_surface_`, retrieves dimensions from `native_window_`, executes `glReadPixels(...)`, and vertically flips rows.
   - Implement `AndroidSurfaceDynamicImpeller::Screenshot()`: delegates to active backing surface (`vulkan_surface_` or `gl_surface_`).
   - Update `AndroidSurfaceMock`: adds `MOCK_METHOD(Screenshot, Screenshot, (), (override));`.

2. **`PlatformViewAndroid` Thread Coordination:**
   - Add `PlatformViewAndroid::Screenshot()`.
   - Dispatch pixel readback to `task_runners_.GetRasterTaskRunner()`.
   - Synchronously coordinate with the calling platform thread using `fml::AutoResetWaitableEvent latch` (mirroring `PlatformViewAndroid::NotifyCreated`).

3. **`AndroidShellHolder` Decoupling:**
   - Update `AndroidShellHolder::Screenshot(...)` to call `platform_view_->Screenshot()` instead of `shell_->Screenshot(...)`.
   - Convert `AndroidSurface::Screenshot` into `Rasterizer::Screenshot` (keeping the existing return type for `platform_view_android_jni_impl.cc` without touching JNI).

4. **Testing & Invariants:**
   - Add unit tests verifying expected dimensions, non-null buffer, and non-blank content (verifying non-zero pixel bytes).
   - Zero changes to `embedder.h`.
   - Zero calls to `Rasterizer::ScreenshotLastLayerTree`.
   - Ratchet dependencies verified clean.

## 3. Invariants & Guardrails
- **I-1 No silent fallbacks:** A failure to read pixels or unconfigured surface returns empty screenshot rather than corrupt or forged pixels.
- **I-4 Behaviour claims backed by tests:** Tests verify both valid dimensions and non-zero pixel data.
- **I-7 Diff cap:** Under 250 lines of production code.
- **I-9 No non-Android embedder changes:** Purely inside `shell/platform/android/`.
- **I-10 No Android in shared code:** Zero modifications to `embedder.h`.

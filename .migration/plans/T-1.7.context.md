# T-1.7 Context: SetApplicationLocale Callback

## 1. Problem Statement
The Flutter framework provides `PlatformDispatcher.instance.setApplicationLocale(Locale locale)` to allow applications to programmatically change their active application-specific locale (e.g. for Android 13+ Per-App Language Preferences via `LocaleManager.setApplicationLocales` or iOS per-app language selection).
Inside the Flutter Engine, Dart calls `PlatformConfigurationNativeApi::SetApplicationLocale(String locale)`, which forwards through `RuntimeController` -> `Engine` -> `Shell` -> `PlatformView::SetApplicationLocale(std::string locale)` on the platform task runner.
While `PlatformViewAndroid` and `PlatformViewIOS` implement `SetApplicationLocale` to update platform state and JNI, `PlatformViewEmbedder` does not override `SetApplicationLocale`, and `FlutterProjectArgs` in `embedder.h` provides no callback mechanism for embedders to receive these events.

As a result, on any embedder using the Embedder API (`embedder.h`), application-level locale changes requested by Dart are silently ignored and dropped.

## 2. Constraints & Invariants
- **C-ABI Backward Compatibility (§6.1 Rule 1 & Rule 2):**
  - Append `set_application_locale_callback` to `FlutterProjectArgs`.
  - In `embedder.cc`, use `SAFE_ACCESS(args, set_application_locale_callback, nullptr)`.
  - Do NOT bump `FLUTTER_ENGINE_VERSION` (§G.5, §G.9 Item 2). Forward compatibility is managed exclusively via `struct_size` and `SAFE_ACCESS`.
- **String Lifetime & Thread Affinity (§6.1 Rule 8 & Rule 9):**
  - The BCP 47 `const char* locale` string passed to `FlutterSetApplicationLocaleCallback` is guaranteed to be null-terminated and valid for the duration of the callback invocation.
  - The callback is invoked on the thread executing the platform task runner.
- **Layering & Scope (§A.1 I-9, I-10):**
  - All modifications are strictly within the embedder API layer: `shell/platform/embedder/`.
  - No Android code or Android platform files (`shell/platform/android/`) may be touched in Stage 1. Android consumers will adopt this callback in Stage 3.
  - No Android-specific types, headers, or semantics; BCP 47 language tags are standard and platform-agnostic.
- **Testing & Verification:**
  - Unit tests in `platform_view_embedder_unittests.cc` verifying dispatch through `PlatformViewEmbedder::SetApplicationLocale`.
  - Integration host tests in `embedder_unittests.cc` verifying that Dart calling `PlatformDispatcher.instance.setApplicationLocale` triggers `set_application_locale_callback` with the expected BCP 47 tag.
